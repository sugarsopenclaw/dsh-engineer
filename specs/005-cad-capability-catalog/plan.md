# 005 — 实施计划

## 阶段 0：公共 staging 契约

- 定义 manifest、CapabilityAtom 和 enrichment JSON Schema；
- 提供标准库实现的校验、进度和下一批工具；
- 用测试证明未知 ID、重复 ID、哈希不一致和未完成状态会失败。

## 阶段 1：COM 原始库存

- 扩展现有 `ExportThcadComApiInventory.ps1`，或新增共享同一反射代码的原子导出器；
- 从 10 个类型库保存方法签名、属性访问器、事件和 ProgID 激活入口；
- manifest 同时保存现有声明级计数，原子计数按拆分规则重新计算；
- 当前会话探针只形成运行时观测，不覆盖类型库事实。

## 阶段 2：.NET 原始库存

- 从 7 个托管程序集逐重载导出；
- 保留程序集版本、SHA-256、声明类型、静态/实例、参数方向和返回类型；
- 单独登记类型、枚举和常量等支持符号，避免把所有字段都误称为 Action。

## 阶段 3：LISP、命令与宏

- 分开保存源码定义、当前运行时符号、CUI 宏和直接命令 token 的证据来源；
- 同一名称的多来源观测通过关系连接，不在原始层抹平；
- 宏保留完整命令串，后续再解析 `INVOKES`。

## 阶段 4：原生候选

- 导出模块与 PE symbol；
- 未知签名保持未知，只做发现线索和模块归属；
- 不生成可调用包装器。

## 阶段 5：Agent enrichment loop

- 每批固定数量、按 `atom_id` 稳定排序；
- 先使用确定性规则生成 getter/setter 等基础分类，再由 Agent 补充简述、领域标签和语义候选；
- 不确定时使用 `unknown` 或 `deferred`，不得猜测；
- 每批独立落盘并执行全量校验，可随时中断恢复。

## 阶段 6：确认后再物化

- 人工抽查各能力面样本和候选等价关系；
- 定义正式 capability Ontology、数据库迁移与导入事务；
- 为 surface、semantic、logic-affinity 分别建立 GraphView，不把坐标写成原子业务属性。
