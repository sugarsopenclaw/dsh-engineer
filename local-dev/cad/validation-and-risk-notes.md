# 样本验证与硬编码风险

当前结论来自七张沈变 DWG，只能表述为“在这七张样本中验证通过”，不代表其他项目、其他设计院、其他 CAD 模板或所有机械图纸都满足。开发目标是发现规律、留下证据、验证规律并利用规律；样本不满足时应报告未识别或歧义，不能为了产出结果强行套用。

## 规律开发总原则（长期约定）

七张图是当前回归样本，不是规则全集。代码可以先解决眼前样本，但每条规律都要按下面三步保存，便于以后换图纸继续修正：

1. **发现信号**：并列收集可能表达同一语义的名称、线型、实体类型、文字、几何和图层，不把某一个字符串当成唯一入口。例如器身中心线同时搜索专名 `器身中心线`、通用名 `中心线` 和 `CENTER*` 线型。
2. **验证信号**：用相互独立的证据提高可信度。例如两条候选中心线在很小范围内相交且近似垂直，会形成比单根线更强的正交轴系候选；图框内位置、跨度、标注、对称拓扑也可继续加证据。高概率仍不等于业务真值。
3. **利用规律**：只有在保留来源句柄、证据、候选和歧义的前提下，才把结果交给定位、镜像、拓扑匹配或后续审图功能。不能确认时继续输出候选，不强行选一个。

各能力保持低耦合：宿主 Adapter 只提供普通观测数据，Core 独立判断；名称和阈值集中配置。新图纸推翻旧规律时，只需给对应小模块增加样本、证据或降级路径，不牵连其他能力。

面向更广泛图纸时，“没找到”“只有单个候选”“候选过多”“暂不支持该实体形态”都属于可预期结果，不应让整轮抽取失败。各模块逐步统一输出 `status`、`diagnostics`、`candidates`、`evidence` 和 `limits`；只有输入损坏、配置非法等程序性问题才作为错误。逐实体处理仍应隔离失败并继续，其余情况返回可读诊断。

## 当前能力的风险点

- 02 图框检测：默认候选层为 `图框层`，只处理轴对齐且每边由单根 Line 构成的矩形。其他图纸可能使用不同层名、Polyline、分段边或旋转图框。
- 03 图框分区：当前要求上下数字和左右字母成对，数字为 ASCII 正整数、字母为单个拉丁字母。其他图框可能只标一侧、使用中文/罗马字符或不同编号方向。
- 04 机械明细表：主路径依赖 `PC_MXB_BLOCK` 和固定的八个中文属性标签，并按“一图最多一张正式明细表”的七图规律建模。炸开表格、改名属性、多张明细表都需要新样本和降级路径。
- 05 技术要求：依赖标题包含“技术要求”、正文带 `N.` 类编号，并默认正文与标题同图层、位于其下方同一文字列。无标题、无编号、多栏、跨层排版可能漏检。
- 06 图层分析：图层归属来自数据库实体，块定义计数不等于最终渲染实例数；块内 0 层继承、嵌套块和属性参照会使最终显示关系更复杂。
- 07 器身中心线候选：当前把层名包含 `器身中心线`、层名包含通用 `中心线`、图层线型包含 `CENTER` 作为并列发现信号，再以图框跨度、共线合并、近似正交和近邻文字做验证。两根在一起且近似垂直会升级为更强的正交轴系候选，但不会自动盖章。这些名称和阈值只经七图回归；Polyline/Xline、旋转视图、块参照中的轴、多视图多轴以及其他命名规范都可能漏检或产生歧义。几何排序不是业务确认，专用层只出现在块定义时也不能认定当前模型空间轴。

## 实现约定

- 样本规律优先做成可配置参数、证据检查或显式 `limits`，避免散落魔法名称和坐标；
- 不能验证时返回“未检测到/歧义/证据不足”，不静默猜测；
- JSON 保留候选、证据、诊断和限制，Markdown 只提供便于阅读的派生结论；
- 新样本推翻旧规律时，先补回归样本，再调整算法与风险记录。
