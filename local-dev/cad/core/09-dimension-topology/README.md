# 09 · 尺寸拓扑与尺寸链分析

`DimensionTopologyAnalyzer.cs` 是宿主无关 Core。THCAD Adapter 只把尺寸类型、测量值、文字覆盖、`DIMLFAC`、定义点、所属坐标空间及关联对象句柄转换成普通观测；算法不引用 Teigha/BricsCAD，也不修改 DWG。

## 与 07、08 的边界

- 07 识别中心线/中心几何，并提供带文字的具名参考轴；它不把参考轴直接等同于对称轴。
- 08 回答“图上有哪些标注、显示什么、由哪些实体构成”，是全图标注清单与以后去标注的候选输入。
- 09 只处理标准线性尺寸，回答“这些尺寸之间形成什么几何拓扑、数值约束和共基准关系”。

同一个 `RotatedDimension/AlignedDimension` 同时属于 08 和 09，两个结果允许重叠：08 保留标注身份，09 补充尺寸链语义。

## 坐标与确定性规则

不直接用世界坐标的“同 X/同 Y”。每组平行尺寸建立局部坐标：

```text
尺寸轴 u = (cos θ, sin θ)
法向   v = (-sin θ, cos θ)
站位   s = point · u
标注层 h = dimensionLinePoint · v
```

因此水平、竖直及旋转尺寸使用同一套规则：

- `xline1/xline2` 投影为尺寸边的两个端点站位；
- 同站位且法向上下文重叠，才建立共享端点关系；仅投影相同但空间相隔很远不会连接；
- 共享端点、位于同一标注层且向相反方向延伸，形成严格连续尺寸链；
- 多个尺寸从同一站位向同侧延伸，形成共基准尺寸；左右尺寸按标注层配对后形成共基准剖面；
- 一个显式尺寸区间恰好由两个子区间拼合时，检验 `parent = child1 + child2` 并保留数值残差；
- 共基准相邻层可派生未画出的差值，并检验左右层增量是否相等；派生量始终标成 derived，不伪装成原图标注。

拓扑只在相同 `owner_scope + owner_block_name` 内计算，不把块定义坐标和模型空间坐标混在一起。

## 输出

整图抽取新增：

- `dimension-topology.json`：尺寸边、站位节点、几何关系、连通组、严格连续链、闭合等式、派生距离、共基准剖面和未支持尺寸类型计数；
- `dimension-topology.md`：面向人和 LLM 的链、闭合关系及基准偏置摘要；
- `semantic-objects.json.dimension_topology` 与 `extraction-report.json` 的尺寸拓扑统计。

关键证据分层：

- exact：DWG 尺寸定义点、测量值、局部轴投影、共享站位和等式残差；
- derived：连续链、共基准配对、包络、层间差值和中点偏置；
- not inferred：构件业务名称、设计意图、应否补标以及“这是对称轴”等结论。

尺寸文字含中文或英文括号时只标记 `reference_dimension_candidate=true`。这说明画法可能表达参考尺寸，但在未取得甲方制图标准前，不把括号含义提升为硬业务事实。`ACAD_DIMASSOC` 当前只保留关联对象句柄作为可追溯证据，不臆解其内部关联点；作者设置的 `DIMLFAC` 原值也随尺寸边保存，供 18 区分显式显示比例与统计比例候选，09 自身不改写尺寸链测量值。

当前 THCAD 活动图对应的 7 个尺寸得到：

- `170 + 230`、`575 + 635`、`825 + 885` 三条严格连续尺寸链；

## 当前边界

第一版只把 `RotatedDimension` 和 `AlignedDimension` 建成区间图。直径、半径、角度、坐标尺寸仍由 08 完整识别，但在 09 中进入未支持类型计数，等待各自的圆/角/坐标拓扑模型。共基准左右配对目前采用法向上下文和标注层距离的确定性贪心匹配；密集交叉排布、多视图重叠、块实例变换、不同 Z/法向或尺寸定义点被人工移动的图纸需要新增样本后再扩展。
