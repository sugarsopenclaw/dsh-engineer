# 04 · 机械明细表知识化

核心实现只有一个源文件：`MechanicalBomKnowledgeBuilder.cs`。

它把 THCAD/PCCAD 原生明细行块 `PC_MXB_BLOCK` 提升成可直接使用的机械明细表知识，不引用 THCAD、Teigha、BricsCAD、COM、文件系统或 JSON。宿主适配器只负责把块属性、证据坐标，以及命名字典 `PC_BOMXHRELATEDIC` 中已经确认的序号标注关系传进来。

## 为什么当前不用表格拓扑

这七张图里的正式明细表不是一堆无语义的线和文字。每一行都是一个 `PC_MXB_BLOCK`，并且稳定带有八个命名属性：

1. 序号
2. 代号
3. 名称
4. 数量
5. 材料
6. 单重
7. 总重
8. 备注

属性标签已经直接表达“这一格是什么”，属性句柄和坐标还能作为证据。因此主路径应优先使用原生语义，准确度和性能都优于先重建线网、再猜文字属于哪个格子。

晓量的严格表格算法会构造线段 arrangement/DCEL，验证每个矩形格及相邻关系，再按空间位置放入文字。它适合作为降级路径：只有图纸没有 `PC_MXB_BLOCK`、只剩炸开的表格线和普通文字时才需要；本版没有复制或依赖该实现。

## 输出知识

- 固定八列的名称、顺序、知识键和预期值类型；
- 每行的原始字符串，原文始终是权威值；
- 序号、数量、单重和总重在可安全解析时附加结构化值；
- 括号数量会保留原文，例如 `(1)`，同时记录数值 `1` 和 `parenthesized` 记法；
- 行块句柄、每格属性句柄、坐标、行包围盒和 `TH_XUHAO` 作为来源证据；
- 每行附加零个、一个或多个图面序号标注，保留 `xuhao_handle`、原始字典键、关联记录句柄/类型、该气泡实体当前是否存在，以及可取得时的 `pointing_position`（指向侧）和 `number_position`（序号侧）；
- 基于序号圆心和指向端的确定性几何建图，输出 `serial_annotation_groups`：连续气泡段、段内连接、成员顺序、唯一共同指向端以及不能成段的单独序号；
- 缺列、重复属性标签、缺号、重号及“序号”与 `TH_XUHAO` 不一致会显式报告。

序号标注不靠 OCR。`PC_BOMXHRELATEDIC` 的键为 `序号#气泡Handle十进制`，例如当前实测的 `1#27196` 中，`27196` 转成十六进制就是 `TH_XuHaoEntity` 句柄 `6A3C`，因此能直接得到：

```text
明细第 1 行（箱壁 / 5TBC.051.A110050.101）
    → PC_BOMXHRELATEDIC 1#27196
    → 图面序号标注 6A3C
```

这里先确认“表格行对应哪些序号标注”。当一个气泡的指向端严格落在相邻气泡圆心连线的中段，且距离和共线残差同时满足尺度相对阈值时，再把它记录为段内连接；连接距离还受序号最近邻距离下四分位数四倍的局部上限约束，避免相隔很远的引线因偶然共线而误成段。整段唯一未指向其他气泡的端点才成为 `resolved_shared_target`。该结果只确认序号段和共同目标坐标，仍不猜目标构件名称。

两个坐标由 THCAD 适配器读取，Core 只负责原样保存，不依赖 `ExplodeGeometry`。当前实测样式中，指向侧是引线端点与两个同心小圆的公共圆心，序号侧是最大序号圆圆心。七图序号侧为 178/178、指向侧为 162/178；没有引线和目标端几何的 16 个对象只记录 `number_position`，`pointing_position` 保持 `null`。

THCAD 整图抽取会新增 `bom-knowledge.json`，也会把同一结果挂入 `semantic-objects.json.bom_knowledge`。当 03 分区检测成功时，结果还会附带整张明细表所在的主分区和覆盖分区。

## 七图验证

- 五张图存在正式明细表，共 208 行：45、24、18、57、64 行；
- 另外两张没有 `PC_MXB_BLOCK`，输出为 0 张表、0 行，不把“没表”误报成抽取失败；
- 208 行全部具有八个属性标签；
- 字段存在不等于字段有值：序号和数量各 208 个非空，代号 179、名称 207、材料/单重/总重各 2、备注 69；空值会原样保留；
- 五张表的序号分别连续为 `1–45`、`1–24`、`1–18`、`1–57`、`1–64`；
- 208 行的 `TH_XUHAO` 全部与“序号”一致；
- 七图命名字典共有 174 条序号关联记录，其中 147 条能附加到同图的正式明细行，覆盖 136 行；一行允许多个标注；
- `5TBC.384.A110050.1_1` 的 45 行全部有标注关系，当前选中的第 1 行稳定对应 `6A3C`；下节油箱 24 行/24 个标注全部一一对上；
- 其他样图同时证明关系不是强制一一对应：有 18 行但只关联 10 行、有 57 行对应 62 条记录、有 64 行而本图没有气泡，也有本图无明细表但保留 27 条气泡关系；
- 截图中的 24 行表已核对，最后一行是 `8TBT.166.T00003.1 / 方钢12×13600 / 1`。

## 当前边界

- 只识别 `PC_MXB_BLOCK` 原生明细行；
- 当前七图规律是一张图最多一张正式明细表，本版也按此建模；
- 不重建炸开后的线框表格；
- 序号标注关联只采用 `PC_BOMXHRELATEDIC` 的已确认键格式；字典可包含历史/残留记录，`entity_present=false` 会原样保留，不把它伪装成当前有效气泡；
- `TH_XuHaoEntity` 的标准 `Explode` 当前返回 `eNotApplicable`，`GeometricExtents` 也不可用；适配器改用 `ExplodeGeometry` 后会输出指向侧与序号侧坐标，但仍不把分解出的圆/引线当正式业务对象，也不推测被指向构件；
- 不把空值、括号数量或异常字符串擅自改写成推测值。
- 序号成段不以“数字连续”或固定图纸单位为条件；没有坐标、实体已残留删除、几何不连通的记录不会被强行并组。
