# 07 · 器身中心线候选分析

核心实现只有一个源文件：`BodyCenterlineAnalyzer.cs`。

它把图框、图层定义、Line 和文字转成可追溯的中心线候选，供以后做“实体在轴的哪一侧”“关于轴的镜像位置”“寻找对称拓扑”等操作。Core 不引用 THCAD、Teigha、BricsCAD、COM、文件系统或 JSON，也不会修改图纸。

## 为什么输出候选而不是直接认定

“中心线”是几何/制图语义，“器身中心线”是更具体的业务语义。当前七张样本里：

- 每张都有 `3中心线层` 等中心线图层或 `CENTER*` 线型，可形成几何候选；
- `5TBC.384.A110050.1_1` 虽定义了 `4-器身中心线`，但该层 7 条 Line 都位于块定义，模型空间为 0，不能仅凭层名认定当前画面中的器身轴；
- 两张图的技术要求正文提到“器身中心线”，共 4 条文字，但文字远离候选轴，属于设计要求而不是对某条线的局部标注；
- 因而七张图当前都是 `geometric_candidates_only`，没有一张被自动标为已确认器身轴。

输出保留每条候选的图层、端点、方向、跨度、源句柄、证据和参与的正交轴系。若同时出现多个合理轴系，会全部保留，只给出几何排序，不把第一名冒充业务真值。

当前实现正是“发现—验证—利用”的一个就事论事实例：发现阶段并列接受专名 `器身中心线`、通用名 `中心线` 和 `CENTER*` 图层线型；验证阶段检查图框跨度、共线续接，以及两条候选是否在很小范围内相交且近似垂直。单根中心线仍可留下，垂直成对的两根会形成更强的正交轴系候选；两者都不会仅凭七图规律自动变成已确认器身轴。

## 七图回归观察

- `5TBC.384.A110050.1_1`：11 条轴候选、5 个正交轴系候选，存在歧义；
- `5TBC.384.A110050.2_1`：5 条轴候选、2 个正交轴系候选；
- `5TBC.426.A110050.1_1`：4 条轴候选、1 个正交轴系候选；
- `5TBC.457.A110050.1_1`：6 条轴候选、2 个正交轴系候选；
- `5TBC.709.A110050.1_1`：4 条轴候选、1 个正交轴系候选；
- `5TBC.709.A110050.1_2`：4 条独立轴候选，没有满足当前相交条件的正交轴系；
- `8TBC.312.A110050.101_1`：2 条轴候选、1 个正交轴系候选，重合/续接线段会合并并保留全部源句柄。

这些数量只是当前参数对七个样本的回归基线，不是其他图纸必须满足的数量。

## 可复用的轴函数

每条 `BodyCenterlineAxisCandidate` 提供：

- `SignedDistance(x, y)`：点到有向轴的带符号距离，可区分轴两侧；
- `ReflectPoint(x, y)`：计算点关于轴的镜像点；
- 稳定方向：接近水平的轴固定从左到右，接近竖直的轴固定从下到上，使带符号结果可重复。

以后“左侧标为法兰，右侧相同拓扑是否也是法兰”不能只靠镜像坐标下结论。合理流程是：先确认器身轴，再镜像候选构件，比较类型、几何、连接关系、邻接关系和尺度，最后把“法兰”标签作为带证据的推断结果，并允许人工确认。

THCAD 整图抽取会生成：

- `body-centerline-analysis.json`：候选、证据、歧义、源句柄和后续对称操作契约；
- `body-centerline-analysis.md`：面向人和 LLM 的简明候选报告。

运行七图与合成回归：

```powershell
& .\local-dev\cad\core\07-body-centerline-analysis\test-body-centerline-analyzer.ps1
```

## 当前边界和硬编码风险

- 默认名称标记为 `中心线`、`器身中心线`，默认线型标记为 `CENTER`；它们都集中在 `BodyCenterlineAnalysisConfig`，不是通用标准；
- 普通候选默认至少跨对应图框方向的 12%，专用图层候选至少 2%；角度、共线距离、续接间隙、正交和近邻文字阈值也都是待更多样本校准的参数；
- 当前只以模型空间 Line 形成轴候选，尚未处理 Polyline、Xline、Ray、弧线、旋转视图，也未展开块参照变换；
- 文字只有在模型空间且靠近某条候选线时才形成直接证据；正文中提到“器身中心线”只会记录，不会自动绑定；
- 一个图框可能包含多个视图和多个中心线，几何排名不等于语义确认；没有足够证据时必须返回候选、歧义或未检测到。
