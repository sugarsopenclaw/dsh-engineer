# 03 · 图框分区检测

核心实现只有一个源文件：`DrawingZoneDetector.cs`。

这里的“分区”是机械图纸图框边缘的字母数字定位区，不是建筑轴网。算法只依赖 .NET Framework 基础类型，不引用 THCAD、Teigha、BricsCAD、COM、文件系统或 JSON。

## 输入与识别依据

- 输入 02 找到的绘图区内框坐标；
- 输入模型空间文字的内容、句柄、图层和有效对齐锚点；
- 在内框上下外侧窄带寻找整数标签，在左右外侧窄带寻找单个拉丁字母；
- 上下同号、左右同字母配对，并检查两侧坐标一致；
- 相邻标签中心的中点作为分区边界。

文字使用有效对齐锚点很重要。这批分区文字是居中对齐，原始 `position` 不是分区中心，`alignment` 才与短分隔线严格对应。

## 输出与定位

- 列标签、行标签、中心坐标、分区边界；
- 两侧文字的证据句柄；
- `LocatePoint(x, y)`：定位一个点，例如 `A16`；
- `LocateBounds(minX, minY, maxX, maxY)`：给实体包围盒返回主分区和覆盖的全部分区。

THCAD 全量抽取会生成独立的 `drawing-zones.json`，同时把结果写入 `drawing.json.zone_detection`。

## 七图回归

- 六张图：每张 `16 × 12 = 192` 区；
- `8TBC.312.A110050.101_1`：`8 × 4 = 32` 区；
- 合计 1040 区；
- 166 条内部边界坐标均能在真实数据中找到上下或左右成对的短分隔线证据；
- 六个“技术要求”标题均位于 `A` 行，具体为 `A14`、`A15` 或 `A8`。

运行：

```powershell

```

## 当前边界

- 只处理轴对齐的绘图区内框；
- 横向标签只接受 ASCII 正整数；
- 纵向标签只接受单个拉丁字母；
- 当前用文字配对完成识别，短分隔线用于回归核验，尚不用于缺失文字的补位。
