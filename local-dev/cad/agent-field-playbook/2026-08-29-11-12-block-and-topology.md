# 11/12：块实例与平面拓扑踩坑

## 为什么耗时长

- **坐标前提错了**：块定义坐标不是显示坐标；镜像、嵌套、MINSERT、0 层和 ByBlock 必须沿 occurrence 路径解析。
- **小图算法上大图失效**：朴素全对全求交和“长线对全图”在 13–16 万段时爆炸，必须用自适应网格、分层粗网格和真实 bbox 候选预算。
- **容差会破坏证据**：近似曲线内部采样点不能当人工端点吸附；吸附若折叠源边，应拒绝并记录，不能删边。
- **成功状态容易误读**：严格 Euler 失败不一定是丢拓扑；本次六图差额逐张恰等于未成面环秩，所以同时保留严格校验和差额对账。
- **宿主不是普通 .NET**：通用反射读取 `Hyperlinks` 创建原生 wrapper，旁数据库释放后终结触发 `AccessViolationException`。可释放包装器必须跳过或在事务内立即释放。

## 最终可复用规则

1. definition 只存一次，occurrence 保存稳定路径、组合变换、有效样式和世界坐标。
2. 12 只消费 11 世界事实；端点吸附、切节点和固定网格均为派生计划，不改源几何。
3. 空间索引先做 bbox 排除，再计入候选预算；超限必须输出 `unsupported`。
4. 大产物不重复嵌入总 JSON；保存独立 artifact 和紧凑摘要。
5. 保存 11 后可用 `replay-saved-instance-facts.ps1` 脱离 THCAD 重放 12，先分清 Core 问题还是宿主问题。
6. CAD 批量回归顺序：合成 → 最小图 → 单张中图 → 单张大图 → 七图；每阶段失败即停。

## 尚未证明

- 七图没有覆盖所有动态块、MINSERT、外参和单位制。
- 采样圆弧/样条不是解析精确曲线。
- THCAD 原生 wrapper 防护已在新宿主进程通过最小图单图端到端复验；连续多图和此前崩溃点的大图仍未复验。
