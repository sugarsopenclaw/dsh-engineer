# THCAD 能力 21：BOM 实例覆盖对账

日期：2026-08-30

## 为什么单独做 21

04 已能得到 BOM 行、序号段和序号指向端；11 已把块 definition 与每次插入 occurrence 分开并统一到世界坐标；13 已提供工程视图和文档区 scope。21 只组合这三类已确定事实，回答“同一块定义还有哪些实例没有被任何已解析序号指向”，给后续机械 Agent 或视觉精读一个有界候选集。

它不回答“这些候选一定漏标”。同一个构件可能在多个视图重复表达，也可能因对称、示意或文档样例而只标一次。把这一步封顶在候选层，可以让确定性算法提供召回，又不抢后续业务解释的工作。

## 算法

1. 对每个 04 `resolved_shared_target` 序号段，用目标 XY 到 11 叶子 world path 求最近距离；距离阈值由图纸叶子范围和中位尺度共同自适应，也允许调用者显式指定。
2. 从叶子 occurrence id 取最后一个 `/ent:` 之前且包含 `/ref:` 的 owner；再查 owner 对应块引用 occurrence 的 `target_definition_handle`。根空间散线没有 owner，明确输出 `not_matchable_loose_geometry`。
3. 全图枚举相同 target definition handle 的块引用 occurrence。11 已把 MINSERT 每个单元格、嵌套和镜像插入展开成独立 occurrence，因此 21 不再猜实例数量。
4. 在分析段之前，先把全部 BOM 序号成员的 `pointing_position` 用同一规则倒排到 owner。当前段命中为 `pointed`，其他段命中为 `pointed_by_other_item`；无人命中且不在文档区才是 `unpointed_candidate`。
5. 实例位置取世界变换平移项，足迹取 owner 下所有叶子 bounds 并集；位置落入的最小非纸张结构 13 区域作为视图 scope，计数不跨视图合并。
6. 每个关联 BOM 行保留 `values.quantity` 原文及 `parsed_values.quantity`，与覆盖计数并列，不执行相等性或缺陷判断。

## 输出与接入

- Core：`local-dev/cad/core/21-bom-instance-coverage/`。
- 整图产物：`bom-instance-coverage.json`、`bom-instance-coverage.md`。
- `extraction-report.json`：`bom_instance_coverage_status`、段数、可匹配段数、未指向候选数、不可匹配数和耗时。
- Bridge artifact id：21。
- Pi：沿用机械 child 的 `thcad_analysis catalog/summary/query`，没有新增固定工作流、工具或子代理。

## 已验证

合成回归覆盖五种情况：三项同定义实例中两项有不同序号证据；散线锚点；四格 MINSERT 加镜像实例；文档区排除；同定义实例被其他 BOM 序号指向。回归同时确认括号数量原文和解析值并存、只读 mutation 契约不变。

## 真图观察

新 Bridge 首次加载后，对当前 dirty 会话 `5TBC.384.A110050.1_1.DWG` 执行一次只读 `extract_current`：`DBMOD` 前后均为 5，桥状态和 current-analysis 均登记 capability 21。

- 35 个序号段；19 个 `computed` 且可按 definition handle 对账；12 个 `not_matchable_loose_geometry`；4 个 `anchor_unresolved`。
- 19 个可匹配段的逐段账本合计 156 项同定义 occurrence 分类：19 项被本段指向、2 项被其他序号段指向、135 项 `unpointed_candidate`、0 项文档区排除。这个合计会在不同序号段锚定同一 definition 时重复列账，不是全图唯一物理对象数。
- 15 个可匹配段存在至少一个未指向候选；2 个段出现 `pointed_by_other_item`，证明全序号倒排在真图上实际生效。
- 9 个段锚定匿名块并按 handle 完成匹配；没有段触发 200 项明细截断；21 本身耗时约 904.8 ms。
- 用户最初关注的序号 19/20/21 被 04 识别为同一序号段，21 锚定 definition handle `30A03`（匿名名 `A$C6960DF88`）。该 definition 在图中枚举到 1 个实例，分类为 1 `pointed`、0 `pointed_by_other_item`、0 `unpointed_candidate`；三行 BOM 原文分别保留“板16×280×350 / 1”“加强铁300×400×100×20 / 2”“法兰 / 1”。
- JSON 逐段验证“4 类计数之和 = definition 实例数”“逐视图计数之和 = definition 实例数”，35 段均无守恒错误；Pi `thcad_analysis summary/query` 已能读取 21。

这些观察只记录该次图纸和 dirty 会话态，不设为跨图纸真值或硬编码断言。135 是继续解释的候选库存，不能写成 135 个漏标。

## 已知限制与下一步真值

- v1 不对根空间散线做拓扑签名匹配。
- 不跨视图合并物理实例身份。
- 匿名块按 handle 对账；动态块只按有效 definition，尚不能按 authoring definition 收束变体。
- 每段默认最多输出 200 项实例明细；超限保留完整分类计数和显式诊断。
- 最终真值验收需由用户在 `.pi/runtime/thcad-workspace` 副本中手工删除一个序号气泡，再重抽确认相应同定义实例进入 `unpointed_candidate`；自动化不得代替这一步修改图纸。
