# AutoCAD 2024 原子能力采集：单 Goal 提示词

下面代码块可整体复制为 Goal 模式任务：

```text
目标：在当前已经打开的 AutoCAD 2024 上，完成一套与 THCAD V24 完全隔离、可复现、可校验的 CAD 原子能力库存。只采集 CapabilityAtom 及其属性，不创建 SemanticCapability，不建立原子之间、原子与 01—07 Logic、业务需求或 AgentRun 的任何关系，不做 THCAD/AutoCAD 对比，不导入 PostgreSQL，不改后端或前端。持续工作到五个库存全部生成并通过验收，再停止并报告。

开始前必须完整阅读根 AGENTS.md、specs/007-autocad-2024-capability-catalog/ 下全部文件、dev-test/visualstudionetframework/probes/autocad-2024/README.md、specs/005-cad-capability-catalog/spec.md、data/pipelines/cad_capabilities/README.md、data/pipelines/cad_capabilities/schemas/ 下与 atom/manifest/enrichment 有关的全部 schema，以及现有 ExportThcad*、ComCapabilityScan.cs、DotNetCapabilityScan.cs、NativeCapabilityScan.cs、PeExportReader.cs。THCAD 文件只作为实现参考；不得运行带默认 THCAD 输出的入口，不得修改、删除或覆盖任何 thcad-v24.*、thcad-v24.semantic 或 data/datasets/curated/cad-capabilities/v1 数据。

先运行 dev-test/visualstudionetframework/probes/autocad-2024/PrepareAutoCad2024CapabilityWorkspace.ps1，并记录现有 thcad-v24.com、thcad-v24.dotnet、thcad-v24.lisp、thcad-v24.command、thcad-v24.native 的 inventory-manifest.json 与 capability-atoms.jsonl 哈希作为只读保护基线。随后做宿主预检：从当前 acad.exe 进程路径和文件版本，再结合 COM/ROT、注册表或 AutoCAD 运行时至少另一类证据，确认目标确为 AutoCAD 2024，记录产品名、完整版本、位数、安装根、活动文档、已加载模块和证据来源。如果没有找到运行中的 AutoCAD 2024，或多个实例无法可靠区分，停止采集并向用户报告具体阻塞，绝不能退回去扫描 THCAD。所有安装文件来源必须落在实测 AutoCAD 2024 白名单路径或实测注册模块中；排除 THCAD、THSOFT 和 BricsCAD 路径。

固定生成五个 inventory：autocad-2024.com、autocad-2024.dotnet、autocad-2024.lisp、autocad-2024.command、autocad-2024.native；每条原子的 observed_host_ids 只能写 ["autocad-2024"]。输出只能进入 data/datasets/staging/cad-capabilities/ 对应的五个 autocad-2024.* 目录。原始 inventory-manifest.json 与 capability-atoms.jsonl 必须由类型库、程序集反射/元数据、LSP/CUI 文件、当前 AutoCAD 会话或 PE 导出表确定性生成，禁止从 Markdown 手抄或由大模型凭记忆补成员。

优先复用公共 C# 扫描内核、Python atomizer、稳定 ID 和 catalog_queue 校验器，为 AutoCAD 2024 新建位于 dev-test/visualstudionetframework/probes/autocad-2024/ 的薄入口。不要复制一套只改名字的 Python 管线；如果必须把既有宿主硬编码改成参数，保留 THCAD 调用兼容性并补自动化测试。AutoCAD 程序集、类型库、ProgID、支持目录和 CUI 范围必须从当前安装实测发现并写入 manifest，不能照搬 THCAD 清单，也不能把预期数量硬编码为通过条件。

按 COM → .NET → LISP/Command/CUI → Native 顺序完成。方法与构造器按完整重载拆分；属性 getter/setter、事件 add/remove、field read/write 分开；同名不同声明类型不得合并；枚举常量等支持符号不得冒充 Action。写入、创建、编辑、删除、变换、保存等有副作用的入口必须照常登记，不能因为本轮不执行它们而排除；但采集阶段不要在用户当前 DWG 上逐个调用这些入口。Native PE 只保存 native_export 候选和真实导出信息，签名未知就保持未知，不生成 P/Invoke。

对 COM、.NET、LISP、Command 库存使用独立 enrichment 补充 classification_status、operation_kinds、domain_tags、中文 summary、confidence 和 evidence，直到 pending=0；原始 atom 永不改写。属性 getter/field_read 可按明确 atom_kind 分类为 read，setter/field_write 分类为 edit，其余依据声明类型、完整签名和来源做可解释的多值分类。不确定就 deferred 并说明原因。semantic_candidates 必须始终为空，不运行 semantic_relations.py。严禁把 THCAD、Teigha、BricsCAD、TH_XuHaoEntity 或其他 THCAD 样图证据附到 AutoCAD 原子；复用旧 enrichment 代码前先补测试证明宿主专属规则不会串入。Native 可以保持 classification_status=pending 和空 operation_kinds，但必须完整统计。

每完成一个技术面都立即验证，失败先修该技术面再继续：严格通过 JSON schema；atom_id 必须匹配公共 canonical_atom_id；无重复、无未知 enrichment ID；manifest 总数、by_kind、source 计数和 atoms_sha256 全部一致。对同一冻结输入连续导出两次，原子顺序、canonical_key、atom_id 和 capability-atoms.jsonl SHA-256 必须字节一致。为新增宿主发现、导出入口和隔离保护补测试，至少覆盖“AutoCAD 输出拒绝指向 thcad-v24.*”以及“AutoCAD 原子不携带 THCAD runtime evidence”。运行现有 cad_capabilities 全套测试和新增测试，确认没有改坏 THCAD 生产器。

在 specs/007-autocad-2024-capability-catalog/tasks.md 中随完成情况真实勾选。结束前重新计算五个 THCAD 原始库存的保护哈希并与基线比较。最后新建 docs/dev/2026-08-28-AutoCAD-2024-原子能力采集结果.md，逐 inventory 报告：宿主和安装证据、扫描边界、来源构件及 SHA-256、声明级计数、原子总数和 by_kind、classification/operation 分布、deferred/pending/错误、两次导出哈希、产物路径、验证和复现命令、明确未覆盖范围。只有五个 inventory 的原始层都通过校验、四个可分类库存 pending=0、Native 全部归账、测试通过且 THCAD 保护哈希完全未变，才算完成。完成后停止，不生成关系、不构建 curated、不入库、不做 API、不做前端，也不自行开始宿主对比。
```
