# Pi–THCAD 运行留档与训练候选

## 结论

从本切片开始，每次 `delegate_thcad_mechanical` 或 `delegate_thcad_visual_overview` 都生成一个唯一 `run_id`，把主 Agent 输入输出、fresh child 完整运行、实际工具结果、视觉输入和当次 01–20 原始产物归到同一 review bundle。它解决的是本地复盘和训练素材保全，不负责自动判定样本质量，也不上传客户数据。

## 保存内容

```text
.pi/runtime/thcad-reviews/
  runs/<run-id>/
    request.json                 # 父提示、委派任务、模型与关联 id
    parent-system-prompt.md
    parent-session.jsonl         # 最终回答落盘后的父 Session 快照
    parent-result.json
    child-system-prompt.md
    child-session/*.jsonl        # fresh child 原生 Pi Session
    child-events.jsonl           # JSON 模式完整 stdout 事件
    child-stderr.log
    child-tool-trace.jsonl       # 工具调用/结果的确定性 join
    child-result.json
    child-inputs.json            # 视觉模型实际收到的图片、哈希与出图元数据
    visual-assessment.json       # 结构化视觉清晰度结果（视觉 run）
    evidence.md                  # 宿主工具投影 + child 保守总结
    artifact-manifest.json       # analysis_id / DBMOD / 文件哈希
    lifecycle.jsonl
    review-manifest.json         # bundle 内文件哈希与训练状态
  objects/sha256/<aa>/<sha256>   # 01–20、父图片和视觉 child 输入内容寻址去重
  cache/
  exports/
```

child 不再使用 `--no-session`，而是为每个 run 使用新的唯一 Session 目录和 id，所以仍不继承父对话或上一次 child 上下文。视觉 run 的 `request.child.role=vision`，实际送模图片先冻结到 CAS；主 Agent 仍只看到有界 evidence，raw child transcript 和整图 artifact 不进入主模型上下文。

## 为什么 evidence 还要保存宿主工具投影

模型可能总结不完整，甚至把 artifact ref 误当 evidence。宿主因此从 child 原始事件按 `tool_call_id` join 调用和结果，写入 `child-tool-trace.jsonl`，并把有界投影附在 `evidence.md` 前部。即使 child 最终正文有问题，review 仍能看到实际工具返回，主 Agent也能发现矛盾。

## 01–20 快照与去重

抽取器仍可按图名更新工作 artifact，但 review store 在 child 结束后冻结：

- `state/current-analysis.json`；
- `artifact_directory` 下全部规则产物；
- 存在时的跨图项目图。

每个文件记录逻辑路径、源引用、字节数、SHA-256、对象引用和源代次指纹。对象库存储实际字节，旧 run 不受后续同名覆盖影响。当前真图一代 43 个唯一对象约 351.7 MB；第二次引用完全相同代次时 `unique_object_bytes_added=0`。

源代次缓存以路径、size、mtime、ctime 组合识别未变文件；首次代次复制时会复查源元数据，最终 `verify` 仍按对象实际 SHA-256 逐项校验。

## Review 与训练候选

```powershell
# 最近运行
.\scripts\thcad-review.ps1 list 10

# 同时校验 bundle 文件和 CAS 对象
.\scripts\thcad-review.ps1 verify <run-id>

# 导出轻量文本候选 JSONL
.\scripts\thcad-review.ps1 export-candidates
```

TUI 中可用 `/thcad-reviews` 和 `/thcad-reviews verify <run-id>`。

导出只组织父提示、图片 SHA-256/CAS 引用、父最终回答、child evidence、模型/用量、analysis_id、DBMOD 和 provenance refs，不把图片 base64 或 351 MB 原始对象嵌进 JSONL。每条默认：

```json
{
  "review": {
    "label": "unreviewed",
    "training_eligible": false,
    "contains_customer_data": true,
    "requires_human_curation": true
  }
}
```

后续只有经过数据授权、脱敏、去重、质量评审和明确标签的子集才能转换成目标训练平台格式。raw Session 中保存的是 Pi/供应商实际暴露的消息和 reasoning 字段，不代表能够取得模型未暴露的内部思维。

## 边界

- 不保存 DWG 二进制；dirty 会话保存的是当次抽取产物和 DBMOD。
- 不自动删除或上传 review 数据；磁盘保留策略另立规格。
- `review-manifest.status=complete` 表示记录链完整，不表示模型回答正确；质量状态始终从 `unreviewed` 开始。
- 旧版 `.pi/runtime/thcad-evidence/` 中已有运行不会自动补齐 child Session 或历史 artifact。
