# 2026-08-25 THCAD 批量抽取链路与数据底座选型

三件事在这一天闭环：THCAD 全自动批跑跑通、七张图天河侧数据收敛为单份权威集、数据底座与部署形态定调。本文是这几件事的关键信息汇总；字段级目录见 `2026-08-24-THCAD全量实体数据能拿到什么.md` 第 11 节，逐图对照见 `2026-08-24-THCAD抽取数据一览表.md` 文末补充。

## 结论

1. **THCAD 可以全自动批跑**：插件 `SHBEXTRACTALL` 旁数据库批量命令 + COM `SendCommand` 触发已启动的 GUI 实例，7 张图约 7 秒抽完，0 失败，不经编辑器、不回写源文件。
2. **数据底座用 TH 侧**：AutoCAD 里 471 个 proxy 在天河全部解成真类，且解不出的恰是去标注任务要识别的标注类对象；标准几何两边 handle 级等价。AutoCAD 降为校验 oracle 和非天河图纸兜底。
3. **部署走客户端分发**：THCAD 插件 + 本机 DSH node；中心退化为不跑 CAD 的规则/报告存证服务。

## 一、自动化链路（已跑通）

背景约束：THCAD **没有 accoreconsole 等价物**（安装目录只有 `thcad.exe` GUI 主程序），AutoCAD 那套 `run-extract.ps1` 无头管线不能照搬。

实际跑通的链路：

```text
trigger-thcad-batch.ps1
  → COM GetActiveObject("BricscadApp.AcadApplication")   （THCAD 沿用 BricsCAD ProgID，实测可拿运行中实例）
  → ActiveDocument.SendCommand: NETLOAD + SHBEXTRACTALL
      → 插件旁数据库循环：new Database(false,true) + ReadDwgFile(只读共享) + DrawingExtractor.Extract
      → 每张图写出 out-thcad/<图纸名>/，已有报告的跳过（SHB_EXTRACT_FORCE=1 强制重抽）
      → 进度 out-thcad/_batch-log.txt，完成哨兵 _batch-done.txt
```

关键事实：

- `DrawingExtractor.cs` 无 Editor / DocumentManager / WorkingDatabase 依赖，纯 Database 级遍历——旁数据库抽取因此成立，且**天然杜绝编辑器开图回写 client-data 的事故**（8-24 那次 DWG 被宿主改写的隐患消掉）。
- 保真验证：最大的 5TBC.426.A110050.1_1（26,038 实体）与 AutoCAD 侧 handle 全对齐，75 个 proxy 全解出真类；试点图重抽与 8-24 手动抽取数字一致（3570 / 0 proxy）。
- 备选路径（未实测）：`thcad.exe <图纸> /b <脚本.scr>` 启动脚本（BricsCAD 系开关，OEM 是否保留待验证），适合冷启动无人值守。

产物位置：`dev-test/visualstudionetframework/` 下 `trigger-thcad-batch.ps1`、`scripts/aggregate-thcad.py`（跨图字段聚合）、`out-thcad/`（数据）。运行手册见该目录 README。

## 三、底座选型：TH 为主，AutoCAD 为校验

判断依据：

- 去标注任务的核心是"认出哪些是标注"。序号、引出、基准、粗糙度、箭头线在 AutoCAD 里全是 `AcDbZombieEntity`（不可炸开、无类型、无几何），在天河里是有 `runtime_class` + 图层 + bbox 的真类，可直接进分类规则。
- 标准几何两边 handle 级零差异，选 TH 不损失几何判定精度。
- TH 侧白拿业务语义：标题栏、明细表、序号↔明细字典、`TH_POWERPARA` 参数化标记——正好覆盖图纸去标注.md 里"文件配对与版本检查""参数明细表读取"两步的输入。
- **写图必须在 TH 侧做**：AutoCAD 存图会把 TH 自定义对象降级成 proxy，等于毁数据。
- AutoCAD 保留：`accoreconsole` 无头批跑能力做 handle 对账/抽样复核（`compare-hosts.ps1`），以及非天河来源图纸的兜底。

## 四、部署方向：客户端分发

形态：

```text
每台设计机器：
  THCAD 内 .NET 插件    右侧面板 UI + 抽取/写图执行器（已有）
  本机 DSH node 进程    Agent 编排层：规则包、工具调用、报告、审计轨迹
                         （即 @shb/cad-tools 那套插件体系的宿主，不另造轮子）
  插件 ↔ DSH：本机 HTTP/WebSocket（CAD Data Gateway 缩成同机进程）

中心（不跑 CAD，无授权风险）：
  轻服务 = 规则包下发 + 报告/证据存证 + 审计汇总
```

为什么优于服务器 CAD Worker 方案：授权用客户已有席位（中心零 CAD 授权问题）；"10 人并发"自然消解为席位并行；DWG 不出机，私有化阻力小；审图定位/高亮直接作用于用户正在看的图。

代价与待管事项：

- 插件和规则包要做分发与版本管理；DSH 仍是 Developer Preview，版本必须钉死（同仓库 AGENTS.md「跟上游一起长」的纪律）。
- 生产端若要求中心统一收 DXF：客户端净化 + 几何一致性校验通过后再上传，中心只存证转发。
- Electron 缓议——只当审定等非 CAD 角色的只读报告壳，不做抽取客户端。
- 对 198 万报价文档的影响：三周可行性闸门里"确认服务器授权"一条可改写为"确认席位分发清单"，风险等级降一档。

## 五、仍未解决

- `TH_*` 专业对象内部业务参数无公开读法（壳可定位，值拿不到；标题栏/明细表已走块属性绕开）。
- THCAD 无无头宿主；`/b` 启动脚本开关在该 OEM 版上未实测。
- 提取器已知 PoC 问题清单（drawing_handle 字段误导、单事务到底、AtomicWrite 非原子等）见 `dev-test/visualstudionetframework/README.md` 末节。
- client-data 里 7 张 DWG 现状均为宿主保存过的版本，`.bak` 是原件；是否恢复待用户决定（见 `docs/research/天河cad实体抽取冒烟.md` 末节）。
