# DSH 官方扩展面与沈变插件化边界

## 结论

DeepSeek Harness 可以作为沈变图纸审查 Agent 的本地产品外壳。它已经为模型接入、Agent 工具、界面品牌、Host/Client 协作和运行时组合提供公开扩展入口。沈变能力应沿这些入口做成独立插件，`harness/` 继续作为只读 submodule 跟踪上游。

当前界面显示的 `DSH Local Build` 不是本项目定制内容。它是源码构建在没有品牌插件占用 Slot 时使用的上游默认值，旁边的七位字符是构建对应的 Harness commit。这个现象同时证明：品牌层已有明确的替换入口，不需要修改侧边栏源码。

## 已确认的官方扩展面

### 1. 模型与搜索 Provider

DSH 的 DeepSeek 适配器支持通过 `DEEPSEEK_BASE_URL` 指定模型端点，通过 `DEEPSEEK_SEARCH_BASE_URL` 指定搜索端点；凭据由官方 credential seam 或受信任的环境层解析。模型目录、思考策略、推理强度、重试策略和视觉请求上限也属于适配器配置。

本项目已经利用这个入口，将 DSH 子进程的模型地址设置为沈变 FastAPI 网关。DSH 保持原有消息序列化、工具循环和 SSE 处理，FastAPI 使用根目录 `.env` 的服务端密钥访问 DeepSeek 上游。

相关实现与上游约定：

- [DSH DeepSeek 适配器说明](../../harness/packages/llm/llm-deepseek/README.zh.md)
- [沈变启动脚本](../../scripts/start-harness-via-backend.ps1)
- [模型网关规格](../../specs/003-harness-deepseek-gateway/spec.md)

### 2. Agent 业务工具

独立插件可以通过公开的 `defineTool`、`register` 和 `ctx.*` 服务为 Agent 增加具有业务语义的能力。沈变项目可据此逐步提供：

- 获取当前 DWG 和选择集上下文；
- 识别生产区域与制造图元；
- 生成图纸净化预览；
- 执行受控删除并导出 DXF；
- 定位、高亮和回写审查问题；
- 运行铁芯叠片一致性校验；
- 查询 FastAPI 提供的规则、知识和业务对象。

这些工具的编排主循环留在本地 Harness Agent。涉及天河专业实体的操作由 THCAD 宿主内的原生 Bridge 执行；FastAPI 提供 Agent 可函数调用的共享接口，不接管本地 CAD 主循环。

### 3. 产品品牌与界面 Slot

DSH 侧边栏已经声明 `sidebar.brand.mark` 和 `sidebar.brand.name` 两个 single Slot。没有插件占用时显示鱼形标记、`DSH Local Build` 和 commit 徽标；部署插件可以分别替换 Logo 与名称。会话首屏还提供品牌标记 Slot，浏览器标签标题则由构建期 `DSH_CLIENT_TITLE` 控制。

沈变品牌插件可以在不修改上游组件的情况下提供：

- “沈变图纸审查 Agent”产品名称；
- 沈变项目 Logo 或联合品牌标记；
- 浏览器标签标题；
- 与当前主题一致的品牌呈现。

相关上游约定：

- [侧边栏 Slot 说明](../../harness/packages/client/ui-sidebar/README.zh.md)
- [官方品牌插件示例](../../harness/packages/client/ui-brand-official/README.zh.md)
- [Web 标题构建配置](../../harness/apps/web/vite.config.ts)

界面扩展以已经声明的 Slot 和公开 Client 插件约定为边界。某个区域没有公开 Slot 时，不依赖其 React 内部组件和私有状态。

### 4. Host/Client 协作与运行时组合

DSH 的 Node Host 承载 Agent、工具和本地服务，Web Client 负责交互呈现。业务插件可以利用公开服务和 Remote 约定，把必要的 Host 能力投影给客户端；具体交互仍应围绕上游已经公开的 Slot、事件和服务实现。

插件通过 profile、Cordis 配置和 patch overlay 进入运行时。本仓 `patches/` 只追加自己的 loader，不按上游 row id 覆盖官方配置。开发时继续从 `harness/` 运行源码，并向 `--patch` 传入绝对路径。

## 沈变插件的建议职责

后续可以按实际功能逐步形成以下边界；名称表示职责，不要求一次性创建全部包：

- `shenbian-brand`：产品名称、Logo、浏览器标题和品牌 Slot；
- `shenbian-api-client`：FastAPI SDK、认证、错误映射和共享查询；
- `shenbian-cad`：THCAD Bridge 能力发现与 CAD 语义工具；
- `shenbian-agent`：图纸净化、叠片校验等任务工具和编排约束；
- `shenbian-review-ui`：净化预览、人工确认、问题定位和导出交互。

第一阶段仍聚焦生产用 DXF 图纸净化，只创建完成这条闭环所需的最小插件。铁芯叠片一致性校验复用相同的 CAD、API 与交互基础后再增加。

## 当前状态

- `harness/` 没有本项目源码改动，当前作为钉住 commit 的 submodule 使用；
- DSH 模型请求已经可以通过进程级 Base URL 进入沈变 FastAPI；
- DSH 自带的密钥设置功能仍然保留，FastAPI 配置服务端 Key 时会替换发往上游的 Bearer；
- 页面仍显示 `DSH Local Build`，因为沈变品牌插件尚未实现；
- THCAD Agent 工具、审查交互和业务 UI 仍按两项核心任务逐步落地。

## 实施约束

DSH 当前处于开发者预览阶段，没有插件 ABI 和磁盘格式稳定性承诺。项目采用以下约束控制升级成本：

1. 不修改、提交或复制维护 `harness/` 内的实现；
2. 只使用文档化的 `ctx.*`、事件、Slot、`defineTool`、`register`、Remote 和配置入口；
3. 不导入 `@deepseek-ai/dsh-*` 内部文件，官方包只作为与当前 Harness 版本对齐的 peer；
4. patch overlay 只加载沈变插件，不覆盖官方配置块；
5. 升级 Harness 时先构建，再验证模型网关、插件加载、关键 Slot 和核心任务闭环；
6. 没有公开扩展入口的需求先重新评估交互设计，避免形成长期上游 fork。

这套边界使产品可以持续获得上游 Harness 能力，同时把沈变业务知识、CAD 操作和客户交付形态稳定地保留在本仓可控的插件与服务层。
