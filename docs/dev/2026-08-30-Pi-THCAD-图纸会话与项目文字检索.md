# Pi THCAD 图纸会话与项目文字检索

## 结论

父 Agent 现在可以先在七图项目文字索引中检索业务词，再按命中图纸打开/激活 THCAD，最后把 BOM 序号交给既有视觉精读。客户原图始终只读；唯一允许写入的根是 `.pi/runtime/thcad-workspace/`。

```text
thcad_project_texts(search "法兰")
  → drawing + bom_item_number
  → thcad_app(open/activate)
  → delegate_thcad_bom_close_reading(item_numbers)
  → Review bundle
```

规格见 [`specs/013-thcad-drawing-session-and-text-index/`](../../specs/013-thcad-drawing-session-and-text-index/spec.md)。原规划写的 006 已被既有 CAD capability API 占用，按 SDD 编号不复用规则顺延为 013。

## V4 桥

程序集为 `Shb.Thcad.AgentBridge.V4.dll`，版本 `0.4.0.0`：

- `SHBTHCADAGENTV4`（Modal）：`status`、`extract_current`、`locate_handles`、`scan_texts`；
- `SHBTHCADAGENTV4APP`（Session）：`open_document`、`activate_document`、`close_document`、`save_document_as`、`save_document`。

THCAD AppDomain 不会热替换同名同版本程序集。本次在 V4 首次旁加载后继续收紧了 save 重载和状态输出；当前 dirty 会话没有为此重启，最终 Release DLL 已构建到 deployment pointer，将在下次正常启动时完整生效。当前会话已真实验证 open/activate/close/scan 和受保护 save-as；工作区普通保存的最终实现采用同机已单独验证成功的 `AcadDocument.Save` 入口。

两个命令共用 pending 目录，但控制脚本会把本次 `request_id` 作为命令输入，Host 只移动并执行这一份请求，同时复核 operation 是否属于 Modal/Session 上下文。控制进程在 THCAD 未运行、忙碌或超时时只回收本次尚未认领的 pending，因此失败的 close/save 不会在后来命令中重放。扫描响应可能达到数 MB，控制脚本 stdout 仍只返回 response 文件位置，TypeScript 从权威 response JSON 读取正文。

文档操作有两层守卫：

1. `documents.ts` 对真实路径、扩展名、根目录和符号链接做校验；
2. V4 再以 bridge root 推导项目根和 workspace，拒绝任何越界写入。

客户图由桥新打开时 `open_document` 强制 `read_only=true`；若用户已把同一客户图可写打开，open 返回 `CLIENT_DOCUMENT_ALREADY_OPEN_WRITABLE`，避免把既有可写会话伪报成只读，但不禁止 Agent 用 activate 读取用户当前现场。`close_document` 对非零或未知 DBMOD 默认拒绝，只在调用者显式传 `discard_changes=true` 时 `CloseAndDiscard`，永不隐式保存。`copy_to_workspace` 默认用文件复制保存磁盘态；`from_session=true` 才调用 save-as 捕获会话态，并回传源 `Document` 路径前后与 `Database.Filename` 变化事实。当前 V24 实测显式 `bBakAndRename=false` 后 `Document.Name/path` 不变、`Database.Filename` 会指向副本；因此保留该显式能力，不把它误写成旁路 side-DB。工作区内的普通保存使用已验证的 `AcadDocument.Save` 入口。

## text-inventory adapter

`local-dev/cad/adapters/thcad/text-inventory/TextInventoryExtractor.cs` 与 01 Adapter 平级，不修改 02–20 Core。它通过 `new Database(false, true) + ReadDwgFile(OpenForReadAndAllShare)` 遍历模型空间、图纸空间和块定义，输出：

- DBText、MText、AttributeReference、AttributeDefinition；
- Dimension 展示文本/测量值、MLeader 文本；
- 块引用名称；
- `PC_MXB_BLOCK`：八列 `fields`、`bom_item_number` 和整行检索文本；
- `PC_TITLE_BLOCK`：30 列标题栏字段；
- Database SummaryInfo。

每条记录保留 source、handle、owner、layer、position、bbox 等定位证据。块属性和结构化 BOM 行同时保留：前者适合精确文字命中，后者让父 Agent 一步取得完整 BOM 行与序号。

## 索引格式

根目录：`.pi/runtime/thcad-bridge/text-index/`。

```text
manifest.json
drawings/<stem>-<path-hash>.texts.jsonl
```

manifest 对每张图记录 SHA-256、size、mtime、记录数、标题元数据、扫描时是否已打开/dirty、JSONL 路径。build 先比较 size/mtime，必要时再算 SHA；SHA 未变且 JSONL 存在时跳过 side-DB。变更图重扫失败时，只要旧 JSONL 仍在，就保留 last-good 条目并记录失败，使搜索能力不因瞬时单图错误缩小，同时 status 仍把它判为 stale。status 还会发现扫描根中新出现但未入 manifest 的 DWG，并分别报告源缺失、JSONL 缺失和未索引；search 遇到单图 JSONL 不可用时跳过该图并返回 partial 覆盖信息。扫描响应只按完整 drawing ref 匹配，不再用 basename 猜测。search 使用 NFKC、大小写与空白归一化包含匹配，也支持显式 regex，以及 source/layer/drawing 过滤和 1–200 的全局返回上限。

## 父 Agent 用法

自然语言“法兰审图”的标准路由：

1. `thcad_project_texts status`，过期或未构建则 `build`；
2. `search(query="法兰", sources=["bom_row"])`；
3. 按图取 `bom_item_number`，用 `thcad_app open/activate`；
4. 对该图调用 `delegate_thcad_bom_close_reading(expected_document=<drawing>, item_numbers=[...])`；该 guard 只防止精读错图，不替父 Agent 固定业务编排；
5. 逐一读取 Review evidence，由父 Agent 做跨图汇总。

索引只代表扫描时的磁盘态。若 manifest 标记 `open_dirty=true`，激活该图后应刷新/读取当前 01–20，不能用磁盘索引覆盖现场会话。
