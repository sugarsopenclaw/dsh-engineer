日期：2026-08-24

宿主：THCAD V24 二维机械设计版 V1.3（内核 23.2.4.0）  
插件：`Shb.Thcad.Extractor` 0.2.0  
图纸：`5TBC.384.A110050.2_1.DWG`（单图实测；**2026-08-25 七张已全部抽完，跨图差异见文末第 11 节**）

**结论：七张 DWG 的数据库实体遍历完整，共 91,605 条，逐图均为 0 proxy、0 failed；标题栏固定 30 格、明细行固定 8 格均完整保留，试点图序号↔明细 24/24 可对上。CAD 符号表只保证当前抽取器的名称级字段，天河专业对象的序号数字、粗糙度值、基准字母等内部业务参数仍拿不到。**

这里的“全量”必须分开理解：

- **遍历全量**：七张图中块表记录下的实体全部走过抽取器；不等于每条实体都拥有 `text`、`xdata`、`bbox` 等可选载荷。
- **机械表格全量**：每个实测标题栏都保留同一组 30 个 tag；208 行明细都保留同一组 8 个 tag，空串也不丢。序号关联的 24/24 只指已生成 `xuhao-bom-links.json` 的试点图，其余图见 §11.4、§11.6。
- **键级全量**：当前定义下共有 455 个字段 ID，完整索引在 [`docs/thcad-extract-fields/`](../thcad-extract-fields/README.md)，口径和逐键补充见 §12。这是“七图实测键 + 抽取器预留键 + 一次性派生文件键”的并集，不是 DWG/THCAD 理论上所有可能字段。

本文前 10 节保留试点图的可读摘要，第 11 节是七图差异，第 12 节补齐键级口径。3570 条试点图元不逐条粘贴；原始 JSON 在：

### 12.1 455、198、257 分别是什么意思

字段库存由七张现行 JSON/JSONL、[`DrawingExtractor.cs`](../../dev-test/visualstudionetframework/ThcadExtractor/DrawingExtractor.cs) 的 Serialize / Dump 字段，以及试点图一次性派生的 `xuhao-bom-links.json` 合并而来。一个字段 ID 对应一个 JSON 路径；同名键按作用域区分，XData 每个实测应用名、根命名字典每个实测键名各算一个字段，但 TypedValue 的每个 code、`geometry.kind` 的每个枚举值不另算字段。

完整机器可读索引是 [`_inventory.json`](../thcad-extract-fields/_inventory.json)，纯字段名索引是 [`_inventory.txt`](../thcad-extract-fields/_inventory.txt)，每字段一篇的说明在 [`fields/`](../thcad-extract-fields/fields/)。覆盖检查：

```text
python scripts/thcad_field_docs/test_field_doc_coverage.py
```

库存来源状态与旧目录覆盖率是两套不同统计，不能混在一起：

| 统计轴 | 数量 | 含义 |
| --- | ---: | --- |
| 抽取器声明且七图集合中至少出现一次 | 410 | C# 字段图和现行数据两边都有 |
| 仅抽取器声明 | 27 | 七图没有对应对象/错误，或值恒为 null 被序列化器省略；含 proxy、error、table/viewport 预留键等 |
| 仅派生数据有 | 18 | 全部来自 `xuhao-bom-links.json`；它由一次性脚本生成，不是 C# 主抽取器直接写出 |
| **库存合计** | **455** | 410 + 27 + 18 |

在本节补写之前，三篇 `docs/dev` 目录按“显式点名某个字段/应用名/字典键”的口径只能对应 198 个，目录独有 0 个，另 257 个只在数据或抽取器字段图中。这个 **198 / 0 / 257 的补全前基线是对的**，详见 [`00-completeness.md`](../thcad-extract-fields/00-completeness.md)；它证明旧目录没有凭空多写字段，但不能证明旧目录已逐键列全。本节补的是那 257 个未展开项的类别、路径和边界，逐键工程解释仍以 455 篇字段页为准。

这个文件只有试点图一份，18 个字段虽然都在数据中出现，但不代表七图都完成了关联派生。`all_xuhao_matched=true` 也只说明该文件内 24 个气泡 handle 找到了实体，不自动证明其它图纸的气泡和明细一一对应。

`errors.jsonl` 的预留字段是 `handle`、`owner_block_name`、`error_type`、`error`；七张均为空。proxy 的 4 个专用字段已列在 §12.3，七张同样没有实例。空文件是“本批未发生”的证据，不应从 schema 库存中删除这些诊断字段。

### 12.6 455 个字段之外仍然拿不到什么

- `TH_XuHaoEntity` 内部序号数字；试点图的数字来自命名字典键和明细行派生关联，不是从气泡对象属性读出。
- `TH_DimRough2010` / `TH_DimRoughA` 的 Ra/Rz/等级值。
- `TH_ParaBasePntUA` 的基准字母，以及 `TH_DimLeaderUA` / `TH_CVArrowLine` 的天河专用控制参数。可见文字或基础几何能通过 explode / 通用继承属性得到，不等于拿到了专业参数模型。
- `TH_BOMRecorder` / `TH_BOMSortRecoder` / `TH_BOMItem2XuhaoAssoiateRecoder` 的私有记录体。
- 当前抽取器未定义的 DIM 深变量、填充边界环、动态块参数求值表、B-Rep、完整 Plot 配置，以及不在 DWG 内的算单/项目树。

因此准确表述是：**本批七图在当前抽取 schema 下遍历完整，455 个键级库存有可复现目录；机械标题栏/明细格子完整，试点序号关联完整；但这既不是 AutoCAD/THCAD 全部潜在字段，也没有突破天河专业对象的私有业务参数边界。**
