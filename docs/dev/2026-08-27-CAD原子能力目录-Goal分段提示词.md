# CAD 原子能力目录：Goal 分段提示词

> 日期：2026-08-27  
> 用法：按顺序把每一段单独交给 Goal 模式。上一段通过验收并报告后，再运行下一段。不要把所有阶段一次塞进同一个无限目标。

## 公共前提

公共 staging 契约已经位于：

- `specs/005-cad-capability-catalog/`
- `data/pipelines/cad_capabilities/README.md`
- `data/pipelines/cad_capabilities/schemas/`
- `data/pipelines/cad_capabilities/catalog_queue.py`

JSONL 原始原子由确定性导出器生成；Agent 只写 enrichment。当前阶段不建 PostgreSQL capability 表。

## Goal 1：COM 原始原子导出

```text
目标：完成 THCAD V24 COM 能力面的确定性 CapabilityAtom 导出，生成可重建、可校验、逐原子且不丢重载的 inventory-manifest.json 和 capability-atoms.jsonl；本阶段不做大模型语义分类，不写 PostgreSQL。

开始前完整阅读根 AGENTS.md、specs/005-cad-capability-catalog/、data/pipelines/cad_capabilities/README.md、三个 JSON Schema、docs/dev/2026-08-27-THCAD-V24-能力面总索引.md、docs/dev/2026-08-27-THCAD-V24-COM-Automation能力盘点.md，以及 dev-test/visualstudionetframework/probes/ExportThcadComApiInventory.ps1、ProbeThcadComRuntime.ps1、ProbeThcadCom32Runtime.ps1。

不要从 Markdown 反向抄 JSONL。扩展现有 COM 反射生成器或新增共享同一套类型库反射逻辑的导出器，让类型库/TlbImp/注册表扫描直接产生原子。生成器代码仍放 dev-test/visualstudionetframework/probes/；产物写到 data/datasets/staging/cad-capabilities/<inventory-id>/，该目录不进 Git。路径必须参数化，默认值可以适配本机，但 canonical_key、atom_id 和 JSONL 内容不得包含本机绝对路径。

覆盖现有 10 个类型库与注册表 ProgID。方法按完整重载签名逐条导出；属性 getter 与 setter 分成两个原子；事件订阅与取消入口分开；ProgID 创建入口记录为 progid_activation；同名但声明接口不同的成员不得合并。每条严格符合 capability-atom.schema.json，atom_id 必须由 catalog_queue.canonical_atom_id 所定义的算法得到。参数保存顺序、方向、完整类型和 optional；返回类型、静态/实例、声明接口、类型库、位数、DISPID/注册表视图等可取得事实全部保留。类型库文件版本和 SHA-256 进入 manifest 与原子来源。

inventory-manifest.json 的 source 计数必须保留接口、声明方法、声明属性、声明事件、ProgID 和转换/反射错误数。当前文档中的 467 接口、3352 方法、4302 属性、60 事件、436 ProgID 只作为本机回归基线，不能硬编码为导出逻辑；若实测变化，报告来源文件哈希和差异。原子计数会因为 getter/setter 和事件入口拆分而不同，必须由实际 JSONL 计算。

稳定排序后写 UTF-8 JSONL，每行一个对象，末尾换行固定为 LF。同一安装快照连续导出两次，canonical_key、atom_id、记录顺序和文件 SHA-256 必须完全相同。运行 catalog_queue.py validate 验证 manifest、哈希、计数和稳定 ID；为导出器增加自动化测试，至少覆盖方法重载、只读属性、可写属性、事件、32 位类型库和同名不同接口不合并。

当前打开的 THCAD 只用于 ProbeThcadComRuntime 记录 observed_on=thcad-v24 和激活可达性。不要把“在 THCAD 中观测到”写成“THCAD 独有”，不要据此声明 AutoCAD 兼容。本阶段不要逐个调用会改图的方法，不要改用户当前 DWG。

持续工作到：产物生成成功、两次导出字节一致、通用 validator 通过、测试通过、source 计数全部可归账。最后报告 inventory_id、来源构件、声明级计数、拆分后的 atom 总数/by_kind、所有错误或 0 错误、产物路径和验证命令。不要进入 COM enrichment，也不要建数据库。
```

## Goal 2：COM 全量 enrichment 循环

```text
目标：只基于已经通过校验的 COM capability-atoms.jsonl，逐原子生成 enrichment part JSONL，直到 pending=0；不能修改原始 atom，不能发明成员，不能把推测写成 verified。

先阅读根 AGENTS.md、specs/005-cad-capability-catalog/、data/pipelines/cad_capabilities/README.md、capability-enrichment.schema.json 和 Goal 1 的最终报告。先运行 catalog_queue.py validate 确认原始库存有效，再使用 next-batch 每次领取固定 100 条，按 atom_id 稳定顺序循环。每批写入 enrichments/part-XXXXXX.jsonl，然后立即对全部 part 运行 validate；成功后才领取下一批。中断恢复时以已有 enrichment 为台账，严禁从头重写已完成 part。

先实现并测试最小确定性分类规则：property_get 通常至少为 read；property_set 至少为 edit；constructor/progid_activation 通常为 create 或 lifecycle；event_subscribe/event_unsubscribe 为 event。规则只能根据 atom_kind 和明确签名产生低风险基础事实。方法名启发式不得直接生成高置信 verified 语义，例如 Delete/Erase 可以提出 delete 分类，但必须引用 member_name/signature 证据并保留合理置信度。

Agent 对每条补充：operation_kinds、简洁中文 summary、可多选 domain_tags、classification_confidence、证据和零到多个 semantic_candidates。不确定参数协议、接收对象或真实效果时使用 unknown、deferred 或低置信 proposed；deferred/failed 必须写清原因。只有 runtime_probe 或 human_review 证据才允许 semantic candidate 标记 verified。不要因为两个接口同名就删除或合并原子。

建议 domain_tags 使用开放字符串，但优先复用已经出现的稳定词：application、document、database、entity、geometry、selection、layer、block、attribute、text、dimension、table、bom、xuhao、paper、plot、file、ui、event 等。不要把当前词表硬编码为不可扩展枚举。

每完成若干批次输出一次 progress，但继续运行直到 pending=0。最终必须通过 validate --require-complete，并报告 classified/deferred/failed 分布、operation_kinds/domain_tags 分布、低置信与 deferred 的主要原因、候选 semantic capability 数量，以及随机抽查至少 30 条原子与签名是否一致。不要建数据库，不要进入跨技术去重。
```

## Goal 3：.NET 原始原子导出

```text
目标：完成 THCAD V24 公开托管 .NET 能力面的确定性 CapabilityAtom 导出，逐重载保存完整签名，并用公共 validator 证明指定程序集快照内无漏项；本阶段不做语义 enrichment，不写 PostgreSQL。

开始前阅读根 AGENTS.md、specs/005-cad-capability-catalog/、data/pipelines/cad_capabilities/README.md、docs/dev/2026-08-27-THCAD-V24-DotNet公开能力盘点.md 和 dev-test/visualstudionetframework/probes/ExportThcadDotNetApiInventory.ps1。不要解析 Markdown；从程序集 ReflectionOnly/metadata 直接生成 JSONL。复用现有依赖解析和 ReflectionTypeLoadException 归账逻辑，但输出必须保留完整签名而不是 MethodName ×N。

覆盖文档当前登记的 7 个程序集。每个公开方法重载、构造器重载单独成为 atom；属性 getter/setter 分开；事件 add/remove 分开；公开字段按可读/可写形成 field_read/field_write，literal 枚举常量不是 Action，不要为了凑数伪装成可执行动作，可以只保留在 manifest source 计数和类型元数据中。继承成员只在真实声明类型登记一次，并保留 declaring type；不要在每个派生类复制一份。

canonical_key 必须使用完全限定程序集逻辑名、声明类型、atom_kind 和规范化签名，不含二进制绝对路径、抓取时间或随机值。保存参数方向、泛型、数组、nullable/by-ref、optional、静态/实例和返回类型；遇到无法解析类型不能静默丢弃，必须进入错误计数和报告。程序集版本、文件 SHA-256 和公开类型/方法重载/属性/事件/构造器/字段/反射错误计数写入 manifest.source。

当前文档的 1647 公开类型、5601 方法重载、5087 属性、222 事件、1196 构造器、7885 字段和 0 反射错误是回归基线，不得硬编码。拆分后的 atom 总数由 JSONL 实际计算。添加自动化测试，覆盖同名重载、静态方法、构造器、只读/可写属性、事件、ref/out 参数、继承声明归属和 enum literal 不误当 Action。

重复导出两次必须字节一致；运行 catalog_queue.py validate。持续到 source 全部归账、无静默跳过、测试和 ruff 通过。最后报告 inventory_id、程序集哈希、声明级基线对比、atom 总数/by_kind、加载错误和产物路径。不要进入 .NET enrichment，不要改 COM 数据。
```

## Goal 4：.NET 全量 enrichment 循环

```text
目标：对已校验的 .NET capability-atoms.jsonl 完成可中断恢复的全量 enrichment，直到 pending=0；保留所有技术原子，不做跨 COM/.NET 合并。

执行方法与 COM enrichment 相同：validate 原始库存，next-batch 每批 100 条，逐批写独立 part 文件，每批后执行全量 validate。先用 atom_kind 做确定性基础分类，再由 Agent 根据完整声明类型、方法名、参数和返回类型补 operation_kinds、summary、domain_tags、confidence、evidence 和 proposed semantic candidates。

特别注意 .NET 名称经常只有在声明类型和返回值上下文中才有意义；不能看到 Get/Set/Add/Remove 就忽略类型直接下结论。纯计算、生成新对象但不写数据库、修改当前 DBObject、修改内存副本、提交事务、保存文件是不同语义，可以使用多值 operation_kinds 和具体 summary 表达。某方法是否对 TH_* 专业对象有效属于运行时支持矩阵，元数据阶段不得直接标记 verified。

已知实测证据可以引用现有文档，例如 Entity.ExplodeGeometry 对 TH_XuHaoEntity 的验证，但只有真正对应的 atom_id 才能连接该证据。其余成员不能借一个成功案例批量标记可用。无法判断的使用 unknown/deferred，不要猜测私有参数协议。

持续到 validate --require-complete 成功。最后报告分类分布、deferred/failed、低置信候选、至少 30 条跨程序集抽查和与 COM semantic candidate 的潜在交集数量；交集只报告候选，不修改或合并原子，不建数据库。
```

## Goal 5：LISP、Command 与 CUI 宏原始导出

```text
目标：把 THCAD 当前可证明的 LISP、命令和 CUI/CUIX 宏证据转成机器原子库存，同时保留来源边界；不能宣称获得“全部原生命令”。本阶段先导出，不做全量 enrichment。

阅读根 AGENTS.md、specs/005-cad-capability-catalog/、data/pipelines/cad_capabilities/README.md、docs/dev/2026-08-27-THCAD-V24-LISP与命令能力盘点.md，以及 ExportThcadLispCommandInventory.ps1、ProbeThcadLispRuntime.ps1。直接复用源码扫描、XML 宏解析和当前会话探针数据，不从 Markdown 抄写。

至少区分：LSP 中有文件/行号的 lisp_function；C: 函数形式的 command；当前 atoms-family 中只在运行时出现的符号；CUI 宏 macro；从宏中确定提取的 command token。不要把 10082 条菜单宏当成 10082 个独立命令；宏必须保留完整命令串和来源文件，将来再建立 INVOKES。相同名字在源码、运行时和多个宏中出现时保留各自 evidence/source，不要凭名字直接删重。

当前文档的 25 个 LSP、194 个源码 defun、65 个源码命令、13 个 CUI/CUIX、10082 条菜单宏、1082 个直接命令 token、5774 个运行时符号和 453 个运行时 C: 命令是本机回归基线，不得硬编码。manifest 必须分别记录三路源计数、解析错误和当前会话标识。CUI 重复/Org 版本仍保留来源事实，后续再建立内容哈希或别名关系。

稳定 ID 和 JSONL 规则沿用公共 schema；必要时对 lisp/command 分成独立 inventory，不能在一个 manifest 中伪造单一 surface。增加测试覆盖文件/行号、大小写规范化、同名多来源、宏与命令不混淆、CUI 解析失败归账。两次导出字节一致并通过 validator 后停止，报告每路计数、atom by_kind 和不可证明的边界，不开始 enrichment。
```

## Goal 6：LISP/命令全量 enrichment

```text
目标：分别完成 LISP、Command、Macro inventory 的 enrichment，直到每个 inventory pending=0；不调用未知命令来猜效果。

逐 inventory 使用 catalog_queue.py 的 validate/next-batch，每批 100 条并独立落 part。源码存在时可以引用 defun 所在文件和函数体作为 source_code 证据；宏存在时根据完整命令串分类；只有名字没有参数协议的运行时符号允许 unknown/deferred。命令名称、中文菜单标题和宏序列可以形成 proposed semantic candidate，但不能自动 verified。

macro 的 summary 应说明它是编排入口，不能把宏内部多个命令的综合效果归到其中任意单个命令。相同命令在 LISP、CUI 和运行时出现时，原子不删除；只提出 alias/equivalence 或 observed-in 多来源候选。最终每个 inventory 均通过 --require-complete，报告 deferred 比例和需要实际交互验证的命令清单，不建数据库。
```

## Goal 7：原生 PE 导出候选

```text
目标：把现有 BRX/ARX/宿主 PE 导出盘点转换为 native_export 候选原子，完整保留模块、symbol、ordinal、架构、文件版本和 SHA-256；绝不猜测 C++ 签名或直接生成 P/Invoke/调用包装。

阅读原生能力文档和 ExportThcadNativeApiInventory.ps1。直接从 PE 导出表生成 JSONL，未知返回类型和参数保持 null/unknown，并在 surface_metadata 标明 symbol evidence。模块没有公开 SDK 头文件或导入库时，enrichment 只能是发现线索或 deferred，不能标记 runtime verified。重复导出稳定、计数与现有盘点可解释、validator 通过后停止。
```

## Goal 8：跨技术语义候选与 Logic 连接设计

```text
前置条件：COM、.NET、LISP/Command 原始 inventory 均已完成，enrichment 均 pending=0，并已由用户确认可以进入下一阶段。

目标：在不删除、不覆盖任何 CapabilityAtom 的前提下，设计独立的 SemanticCapability 与候选实现关系数据集，使不同技术但功能相同的原子可以聚类，并能连接 local-dev/cad 01—07 Logic。先写规格和 schema，再生成候选，不写 PostgreSQL。

候选匹配必须综合 operation_kinds、domain_tags、声明类型、完整参数/返回值、summary 和已有 runtime evidence；同名只能作为弱信号。每条关系保存 proposed/verified/rejected、置信度、依据和产生者。典型形式是多个技术原子 IMPLEMENTS 同一个语义能力，例如 .NET Entity.Erase、COM IAcadEntity.Delete/Erase、LISP/Command _ERASE 都保留并连接到“删除 CAD 实体”，不能合并成一个 atom。

同时盘点 local-dev/cad 的 01—07 实现，只有代码中真实调用或已有文档/运行证据支持时才建立 LOGIC_USES_CAPABILITY；不要根据“看起来可能会用”写成事实。输出 surface、semantic、logic-affinity 三种 GraphView 的数据语义，坐标属于 view，不属于 atom；第一版坐标使用按 inventory_id+atom_id 固定种子的稳定随机布局。

完成规格、schema、候选数据、冲突/低置信报告和人工抽查后停止，等待用户确认是否物化数据库。
```

## Goal 9：运行时支持矩阵

```text
前置条件：用户已经选定一批高价值 CapabilityAtom，并明确同意做运行时探针。不要对全部几万原子盲目调用。

目标：为选定原子建立“元数据存在 → 入口可达 → 特定接收对象/前置条件下行为验证”的支持矩阵。每个 probe 必须绑定 atom_id、宿主版本、位数、许可证、图纸/实体样本、参数、预期观察、实际输出、耗时和错误类型；失败、not_applicable 和 blocked 都是有效结果。

当前打开的 5TBC.384.A110050.1_1.DWG 在最近探测时 read_only=false、saved=false，因此写入、编辑、删除和保存类 probe 不得在这份活动原图上执行。使用明确的临时副本或专用最小测试图，验证前后记录实体数量、句柄/属性变化和输出文件哈希。这不是把写能力排除掉，而是保证测试结果可复现且不污染用户样本。

一个 probe 只验证明确范围，不能用某基类方法在一个对象成功推导所有 TH_* runtime_class 都支持。结果写入独立 probe JSONL，并只把有 runtime_probe 证据的 semantic candidate 升级为 verified。完成选定批次后报告支持率、前置条件、错误分布和推荐正式适配入口。
```

## 数据库阶段的停止条件

不要把“Goal 8 完成”自动理解为允许建表。只有用户明确说“这批 JSONL 可以入库”后，才新开数据库、API 和图谱可视化规格。届时 JSONL 仍是可重建事实源，PostgreSQL 只是查询物化层。
