# Pi–THCAD 视觉概览与晓量能力取舍

## 已落地结论

当前主 Agent 新增 `delegate_thcad_visual_overview`。它先核对活动图、DBMOD 和 capability 02 图框代次，再由 THCAD 按图框窗口导出一张 PNG；独立视觉 child 固定使用 `deepseek/deepseek-v4-flash-vision-exp`，只判断整图是否足以做宏观导航。主 Agent必须读取 `evidence.md`，把宿主确定性元数据与模型观察分开表述。

DeepSeek 官方视觉接口支持 JPEG、PNG、GIF 和 WebP，图片放在 user message 的多模态 content 中；本地图片可用 base64 data URL。官方同时说明大图会自动缩放至总像素约 `800×800`、单图最多 384 image tokens，因此整图视觉天然适合布局/清晰度门禁，不适合精读尺寸、明细或技术要求。[官方视觉指南](https://api-docs.deepseek.com/zh-cn/guides/vision)

## 当前实现

```text
capability 02 frame bbox
  → THCAD COM 宿主校验（必须是 thcad.exe）
  → 保存布局 / TILEMODE / VIEWCTR / VIEWSIZE / DBMOD
  → ZoomWindow(frame + 0.5% padding)
  → PNGOUT
  → 恢复现场并复核 DBMOD
  → PNG 签名、尺寸、SHA-256、墨迹率和内容 bbox 校验
  → fresh Pi Vision child（no tools / no extensions / no parent context）
  → strict assessment JSON
  → review bundle / CAS / evidence
```

当前安装未暴露可直接使用的 raster PC3，设备表中没有 `PublishToWeb PNG.pc3`；为了不依赖打印机驱动，本切片使用 THCAD 已安装且真机可达的 `PNGOUT`。它仍由确定性图框窗口驱动，但准确 provenance 是 `thcad_pngout_frame_window`，不能写成 PC3 PlotToFile。

真机样图 `5TBC.384.A110050.1_1.DWG` 的 frame-1 `[0,0]–[16120,11480]` 得到 `1372×798`、403855 字节 PNG，墨迹率 `0.189357`，DBMOD `21→21`。视觉 child 返回 `overview_only`、置信度 0.95：整体视图、表格、说明和标题栏位置可导航，但小尺寸、BOM 与技术要求不可读，需要局部图。这正是当前能力的预期边界。

## 踩坑记录

- 一开始把出图动作加进已经加载的 `.NET AgentBridge`。新 DLL 虽能编译和版本化部署，THCAD 当前进程仍绑定旧程序集与旧命令，重复 `NETLOAD` 不会热替换同名命令，因而返回 `UNSUPPORTED_OPERATION`。结论：新增 .NET 命令需要新命令名/新程序集身份或重启宿主；本切片不要求重启，故撤回该改动。
- COM 类型库有 `PlotToFile`，不代表当前机器存在目标 PC3。运行时设备只有系统 PDF/打印机，不能把库存能力直接当成可用出图链。
- 桌面截图会受窗口遮挡、缩放、主题和对话框影响。使用 CAD 自身的图形导出，并在送模前做空白/哈希/尺寸校验，能把“看错窗口”挡在模型之外。
- `PNGOUT` 会临时改变视图和 TILEMODE。动作必须保存现场、用 DBMOD guard 包裹，并在 finally 中恢复；失败时恢复异常也必须进入稳定错误。

## 对晓量视觉能力的扬弃

晓量中最有价值的不是某个 Python/模型实现，而是“确定性导航 → 受控出图 → 视觉质检 → 坐标/实体回证”的结构。结合沈变已有 01–20，建议按以下顺序吸收。

### 下一步优先吸收

1. **语义区域优先于盲分块。** 晓量的 q1–q4 多分辨率策略保留为区域缺失时的后备；沈变正常链路先用 13 工程视图区、03 图框分区、04 BOM、05 技术要求和标题栏 bbox 生成有名字的 crop。
2. **局部精读与概览解耦。** BOM 构件精读可根据用户任务直接运行，不以 `overview_only`、数字置信度或其他模型自评为前置。省略序号时工具覆盖当前图全部可解析 BOM 序号段。
3. **图像—坐标—实体 sidecar。** 每张局部图同时保存世界坐标 bbox、analysis_id、DBMOD、区域来源及其中的实体/标注 handle；视觉观察必须能回到 01–20 确定性证据。
4. **更强 frame sanity。** 吸收晓量的空白、裁切、错误窗口和 fallback 思路，并增加沈变已有的 frame 几何、墨迹率、content bbox、活动图/DBMOD 校验。
5. **出图指纹与缓存。** 以 document、analysis_id、DBMOD、frame/region bbox、显示配置、renderer 版本、prompt/model 版本组成 fingerprint；同一代次不重复出图或调用模型。
6. **动作后的视觉复验。** 未来真正开放改图时，用 before/after 同区域图检查明显错位、遮挡和遗漏；它只能做复验候选，不能代替事务、实体 diff、撤销和审批。

### 保留为后期选项

- 对极密集图纸做二级/三级自适应 zoom；用七张样图和现场图先验证不遗漏率、裁剪连续性和跨视图一致性。
- 把视觉难例、区域选择和模型判断纳入评测/训练候选；必须经授权、脱敏和人工标签，不能把模型自评当金标。
- 视觉索引可借鉴晓量 `visual-index.ts` / `visual-contract.ts` 的版本化契约，但索引键应绑定沈变 analysis artifact，而非另建一套真相源。

### 明确不照搬

- 不引入 AutoCAD Python COM sidecar：沈变已有 THCAD .NET 数据面和已验证 COM 控制面。
- 不使用桌面/窗口截图作为正常链路；它只可作为诊断兜底，且必须显式标为非确定性来源。
- 不复制 Qwen 专用网关参数、登录、Electron UI 或建筑业务提示词。
- 不让视觉 OCR 覆盖 04/05/08/09 等可由 CAD 实体直接取得的 BOM、文字、标注和尺寸事实。
- 不把四象限递归当作默认业务口径；优先由 BOM 序号段、视图区、技术要求等确定性语义边界决定出图范围。

## 后续实施路线

- V1（本次完成）：02 图框整图、真实性/清晰度门禁、完整 review 留档。
- V2（已完成 BOM 切片）：04 序号段驱动的具名局部图，可直接跑单段或全 BOM。
- V3（BOM 切片已完成）：每张图附实体 handle/坐标 sidecar，视觉解读回证到 04/08/11/13。其他语义区域继续复用该架构。
- V4：面向未来写动作的 before/after 视觉复验与缓存。
- V5：七图及现场样本的可读性评测集、人工标签和模型/费用回归。

实现参考位于晓量冻结快照的 `visual-index.ts`、`visual-contract.ts`、`frame-sanity.ts`、`detail-dataset.ts` 和 AutoCAD `plot.py`；只参考模式，不把其运行时或业务假设带入本产品。
