# 先给结论

这两个场景都可以做，但必须按照**工业软件项目**而不是“大模型应用项目”来实施：

* **铁芯叠片校验**：适合作为真正的“智能审图”样板，核心是参数反演、CAD 矢量几何重建、坐标对齐和规则校验。
* **图纸去标注与 DXF 净化**：适合作为更快落地的生产自动化场景，核心是 CAD 图元分类、生产几何保护、白名单重建和输出一致性验证。

两者共享 CAD 读取、任务调度、图纸标准化、报告和私有化部署底座，但业务算法完全不同。

原始需求覆盖 17 类组件、天河 CAD V21、DWG，以及未来 Creo 衍生二维图纸，使用对象还覆盖设计、校核、审查、审定全过程。这个范围不可能用一个“通用审图大模型”在一期内可靠完成。

如果由我来做，我会坚持四个原则：

1. **矢量 CAD 是判定依据，图片和视觉模型只做辅助。**
2. **确定性规则负责通过与不通过，大模型负责组织、解释和处理非结构化信息。**
3. **永远不直接改原图，只生成审查副本或新的生产 DXF。**
4. **无法可靠解析的图纸必须明确转人工，不能“猜着通过”。**

# 一、两个场景共用的技术底座

你们目前已经跑通了 AutoCAD .NET Framework 4.8、`accoreconsole`、DWG 实体批量抽取，这一点非常关键。项目不需要从零开始研究 DWG，而应在现有抽取器上增加标准化、规则和写图能力。

## 1. 总体架构

```text
DWG / 明细表 / 规则配置
          │
          ▼
     文件预检与版本匹配
          │
          ▼
AutoCAD 原生 CAD Worker
打开、解析、写出 DWG/DXF
          │
          ▼
标准化 CAD 中间模型
图元、图层、块、视图、标注、拓扑、业务对象
          │
          ├───────────────┐
          ▼               ▼
铁芯叠片规则包       去标注净化规则包
几何重建与比对       图元分类与白名单输出
          │               │
          └───────┬───────┘
                  ▼
          证据链与质量检查
                  │
                  ▼
       报告 / 标注副本 / DXF / JSON
                  │
                  ▼
              人工确认
```

## 2. CAD 原生处理层

建议继续使用：

* **C#、.NET Framework 4.8**
* AutoCAD `acdbmgd.dll`、`accoremgd.dll`
* `accoreconsole.exe` 批处理
* 天河 CAD 对应运行环境或 Object Enabler
* 每个文件独立进程或定期回收 Worker

主要抽取内容：

* Line、Arc、Circle、Polyline、Spline；
* BlockReference 及嵌套变换矩阵；
* Dimension、Leader、MLeader；
* Text、MText、Table；
* Hatch、中心线、剖切符号；
* Layer、Linetype、TextStyle；
* ModelSpace、PaperSpace、Viewport；
* 图元 Handle、扩展数据、包围盒；
* Xref、代理实体和自定义实体状态。

这里不建议把 `ezdxf` 或其他通用解析库作为主读取链路。天河 CAD 图纸可能存在代理实体、自定义对象和特殊标注，只有 AutoCAD 兼容运行环境更有可能保留完整图形语义。

对于不能正常解析的代理实体，应采取：

1. 安装对应 Object Enabler；
2. 尝试在内存中 Explode 为标准图元；
3. 若仍无法取得准确矢量数据，则标记该图纸“不支持”，而不是转成截图后强行判断。

## 3. 标准 CAD 中间模型

建议把 DWG 解析结果统一成内部数据模型，而不是让每个场景直接调用 AutoCAD API：

```text
DrawingDocument
├── Metadata
│   ├── 项目号
│   ├── 图号
│   ├── 版本
│   ├── 单位
│   └── 产品类型
├── Spaces
├── Views
├── Blocks
├── Entities
│   ├── Geometry
│   ├── Annotation
│   └── Symbol
├── BusinessObjects
│   ├── Lamination
│   ├── Hole
│   ├── MainContour
│   └── ProductionContour
└── Relations
```

所有图元保留：

* 原图 Handle；
* 所属图层；
* 所属块及嵌套路径；
* 原始坐标；
* 归一化坐标；
* 识别类别；
* 识别依据；
* 置信状态。

后续无论做铁芯、线圈、油箱还是散热器，都是增加新的业务对象识别器和规则包，而不是重写 DWG 读取程序。

## 4. 规则执行方式

规则分成两类：

### 硬规则

由程序直接判断：

* 数量是否一致；
* 坐标偏差是否超过公差；
* 孔径是否一致；
* 轮廓是否缺边；
* 是否存在交叉、自相交；
* 图中是否仍含尺寸标注；
* 输出几何是否与原生产几何一致。

### 软规则

需要大模型或人工协助：

* 技术文字属于内部说明还是生产所需；
* 某张图是否属于特殊型号；
* 某一异常是否可以接受；
* 新增企业规范如何转成机器规则；
* 异常原因和整改建议如何表述。

大模型不能直接负责毫米级几何通过判定，也不应直接决定删除某一生产图元。

# 二、场景一：铁芯叠片图与总图一致性校验

## 1. 一期场景应如何定义

原会议记录中的目标是：

* 输入天河 CAD V21 的 DWG 和参数化明细表；
* 根据明细表反向生成叠片轮廓和开孔点位；
* 与总图对应区域进行比对；
* 检查叠片之间是否存在轮廓错位；
* 当前人工依靠图纸重叠法核对，每份图纸约耗时 1～2 小时。

但目前仍缺少字段释义、图形还原规则、轮廓允许公差和错位判定标准。

因此，一期不能定义成“检查所有铁芯错误”，而应定义成：

> 针对一个铁芯产品系列、一种参数明细表格式和不超过三种固定制图模板，实现参数表重建图形与总图实际图形之间的轮廓、孔位、尺寸和叠片错位校验。

一期不包含：

* 所有铁芯产品系列；
* 任意历史图纸模板；
* 铁芯磁路设计正确性；
* 损耗、电磁性能计算；
* 自动优化铁芯方案；
* 自动修改原始设计图；
* 未提供明确规则的经验型审查。

---

## 2. 真实技术路线

## 第一步：先解决文件配对和版本问题

工业现场最容易被忽略的问题不是几何算法，而是拿错版本。

必须为每次审查建立输入清单：

```text
项目号
产品型号
总图图号
总图版本
铁芯叠片图图号
叠片图版本
明细表编号
明细表版本
生成时间
```

系统首先检查：

* 图号是否属于同一项目；
* 总图和叠片明细表是否为对应版本；
* 是否存在“图已修改、表未修改”的情况；
* 是否缺少必要文件。

版本无法确认时，不进入几何校验，而是直接输出“文件配对异常”。

这一步很重要，因为否则系统会准确地发现大量“差异”，但差异实际上只是两个版本不同。

---

## 第二步：建立参数明细表字段字典

明细表必须转成结构化数据，不能让大模型临时猜字段。

需要特变提供：

* 字段名称；
* 字段含义；
* 单位；
* 是否必填；
* 取值范围；
* 与图形对象的对应关系；
* 计算公式；
* 版本变化规则。

常见字段可能涉及片宽、片长、级数、孔径、孔位、中心距、斜接或搭接参数等，但具体内容必须以特变实际明细表为准。

表格读取方式按优先顺序：

1. Excel、CSV、数据库接口；
2. DWG 中的原生 Table；
3. 固定格式文本；
4. 最后才考虑 PDF 或图片识别。

如果当前已经存在“参数化计算脚本”，最优方案不是重新推导全部设计公式，而是：

> 将现有参数化脚本封装成可调用模块，或者以其输出作为权威预期结果。

这会大幅降低规则复刻错误。现有脚本应被视为“可执行的业务规范”，而不是被大模型替代。

---

## 第三步：从 DWG 中定位需要校验的视图

需要识别：

* 总图中的铁芯对应区域；
* 叠片主视图；
* 侧视图或其他多视图；
* 轮廓线；
* 开孔；
* 中心线和基准线。

第一版不应追求“任意图纸自动找到所有视图”。

我会采用三级策略：

### 一级：明确图层或块名

如果目标区域有稳定图层、块名或属性，直接定位。

### 二级：业务锚点定位

通过：

* 图号；
* 标题文字；
* 对称轴；
* 中心线；
* 特定孔组；
* 外包围轮廓；

建立候选区域。

### 三级：人工一次性框选

如果历史图纸非常混乱，一期允许设计人员第一次配置模板时框选“总图铁芯区域”和“叠片视图区域”。

框选结果保存为模板，后续同类图纸自动套用。

这比为了演示“全自动”而投入大量不稳定的视觉识图更符合工业现场。

---

## 第四步：由参数表生成标准叠片几何

系统根据参数明细表生成一份独立于原图的“预期叠片模型”：

```text
LaminationSet
├── LaminationLevel 01
│   ├── OuterContour
│   ├── Holes
│   ├── ReferenceAxis
│   └── ExpectedDimensions
├── LaminationLevel 02
└── ...
```

生成结果至少包含：

* 外轮廓；
* 所有转折点；
* 线段和圆弧；
* 孔数量；
* 孔中心；
* 孔径；
* 基准轴；
* 层级或级次；
* 参数来源字段。

这份预期几何应同时输出为：

* 内部矢量对象；
* 可叠加到 DWG 的辅助图层；
* 铁芯叠片矩阵数据；
* 便于人工查看的预览图。

---

## 第五步：坐标、方向和比例对齐

不能直接比较两个图形的绝对坐标，因为它们可能位于不同图纸位置、不同视图或不同布局空间。

应使用稳定特征进行对齐，例如：

* 中心线；
* 对称轴；
* 指定基准点；
* 两个或多个稳定孔中心；
* 轮廓端点；
* 图纸已有基准坐标。

正常情况下只允许：

* 平移；
* 旋转；
* 必要时镜像；
* 明确存在视图比例时的统一缩放。

不建议使用任意仿射变换，因为仿射变换可能把本来错误的几何“拉伸到一致”。

对齐后必须记录：

* 使用了哪些基准；
* 平移量；
* 旋转角度；
* 是否发生镜像；
* 比例系数；
* 对齐残差。

对齐残差超过阈值时，系统不能继续判定，应提示“视图无法可靠对齐”。

---

## 第六步：执行矢量级规则校验

不能仅做图片重叠或像素差异，应直接比较 CAD 几何对象。

建议第一批规则如下：

| 规则类别   | 判定内容                 |
| ------ | -------------------- |
| 明细表完整性 | 必填字段、类型、单位、范围是否正确    |
| 轮廓数量   | 预期叠片轮廓与实际轮廓数量是否一致    |
| 轮廓尺寸   | 长、宽、斜边、台阶等关键长度是否一致   |
| 顶点位置   | 各特征点坐标偏差是否超过公差       |
| 轮廓形状   | 是否缺边、多边、断开、自相交       |
| 孔数量    | 实际孔数与明细表是否一致         |
| 孔径     | 实际孔径与预期孔径是否一致        |
| 孔位     | 孔中心位置和中心距是否符合要求      |
| 叠片错位   | 相邻级次之间是否出现不允许的轮廓偏移   |
| 多视图一致  | 主视、侧视等对应尺寸是否一致       |
| 标注一致性  | 标注显示值、真实测量值、参数表值是否一致 |

这里需要区分两类公差：

### 数值计算公差

用于解决 CAD 浮点数误差，例如两个理论上相同的点坐标存在极小数值差异。

### 工程判定公差

由特变确定，例如：

* 轮廓允许偏差；
* 孔位允许偏差；
* 孔径允许偏差；
* 相邻叠片允许错位量。

工程公差必须由业务专家签字确认，不能由软件团队自行猜测。

在算法实现上，可以结合：

* 特征点距离；
* 线段长度和角度；
* 圆心及半径；
* 点到线距离；
* 多边形异或面积；
* 轮廓 Hausdorff 距离；
* 拓扑关系；
* 孔与外轮廓的相对位置。

但最终报告不应只输出一个抽象相似度，而要输出：

> 预期孔中心为 `(1250.0, 340.0)`，实际孔中心为 `(1251.3, 340.2)`，偏差 `1.32 mm`，允许偏差 `0.50 mm`，不通过。

---

## 第七步：生成可追溯证据

每一个问题必须包含：

* 规则编号；
* 图号和版本；
* 原图图元 Handle；
* 预期值；
* 实际值；
* 允许公差；
* 偏差值；
* 问题等级；
* 图纸坐标；
* 局部截图；
* DWG 高亮位置。

建议生成一份审查副本：

* 原图保持不变；
* 预期轮廓放入一个辅助图层；
* 实际异常图元放入一个异常图层；
* 用引线标出问题编号；
* 报告中的问题编号与 DWG 一一对应。

这样设计人员能够点击问题直接定位，而不是阅读一份脱离图纸的文字报告。

---

## 3. 这个场景最难的地方

### 难点一：参数表不是完整的机器规范

目前最大的风险不是算法，而是：

* 字段是什么意思；
* 字段之间如何计算；
* 哪些字段控制哪段轮廓；
* 特殊型号如何处理；
* 参数表和原设计脚本谁是权威来源。

没有这部分，任何报价都只能是可研报价。

### 难点二：总图对应区域自动识别

如果图层、块名和视图布局不稳定，自动找到目标轮廓会很困难。

现实做法应是：

* 先支持固定模板；
* 或要求客户增加简单的业务标识；
* 或允许一次性人工框选；
* 而不是一开始要求视觉模型理解所有历史图纸。

### 难点三：图纸对了，但标注错了；或者标注对了，但几何错了

系统必须分别检查：

* CAD 真实几何；
* Dimension 的真实测量值；
* Dimension 的显示文字；
* 参数表值。

不能只读取标注文字。AutoCAD 标注可能存在文字覆盖，显示值正确并不代表真实几何正确。

### 难点四：产品系列扩展并非简单增加样本

不同铁芯系列可能有不同参数体系、轮廓生成规则和制图模板。扩展一个新系列，可能接近新增一个规则包，而不是把图片多训练几轮。

---

## 4. 实事求是能做到什么程度

在以下范围内：

* 一个铁芯产品系列；
* 一种明细表格式；
* 一至三种图纸模板；
* 客户提供字段字典和生成规则；
* 客户给出明确工程公差；
* DWG 代理实体可正常解析；

可以做到：

* 参数表自动读取；
* 叠片轮廓和孔位自动生成；
* 总图与叠片视图自动或半自动定位；
* 矢量级轮廓和孔位比对；
* 规则级问题高亮；
* 自动生成审查报告；
* 将原来 1～2 小时的人工重叠核对，压缩为数分钟自动计算和约 5～15 分钟人工确认。

合理的一期目标是：

* 支持范围内文件解析成功率达到 95% 以上；
* 明确定义的几何错误具有很高的可重复检出率；
* 端到端自动完成率约 85%～95%；
* 剩余异常图纸进入人工复核；
* 不承诺识别规则清单之外的所有设计错误。

它可以成为可靠的**辅助审查工具**，但不应在一期宣传为替代审查、审定人员。

# 三、场景二：图纸去标注与 DXF 生产净化

原会议记录表明，这个场景计划删除图框、剖视图、放大图、尺寸标注、剖切符号、中心线、辅助线和内部技术文字，输入 DWG、输出 DXF，并且已经形成一定的标准化删除规则和小范围试点。真正尚未明确的是生产端接口、服务器承载和验收标准。

这个场景比铁芯审图更容易较快落地，但有一个非常重要的认识：

> “删除标注”本身不难，难的是确保没有删除生产设备真正需要的几何。

---

## 1. 一期必须先定义“生产 DXF 合同”

不能只给一份“删除对象清单”，还必须给出“最终允许保留什么”。

需要和生产端确认：

* 目标生产设备或编程软件；
* 支持的 DXF 版本；
* 支持哪些图元；
* 是否接受 Spline；
* 是否要求 Polyline 闭合；
* 是否需要圆心、中心线；
* 是否保留折弯线；
* 是否保留孔中心；
* 是否保留零件编号；
* 单位是毫米还是其他；
* 一张 DXF 是否只能包含一个零件；
* 图形原点、方向和坐标要求；
* 图层名称和颜色是否有特殊含义。

尤其要警惕“删除中心线”这条规则。

有些生产设备只需要闭合轮廓，中心线应删除；但另一些钻孔、折弯或定位流程可能依赖中心线、孔中心或辅助加工线。最终标准必须由目标设备接口规范决定，不能只依据设计人员的主观理解。

---

## 2. 采用“白名单重建”，而不是在原图上不断删除

我不会在原 DWG 上执行大量 `Erase()` 后直接保存。

更安全的做法是：

```text
读取原 DWG
    ↓
对每个图元分类
    ↓
Keep / Delete / Review
    ↓
仅将 Keep 图元复制到一个全新的 CAD 数据库
    ↓
进行生产几何检查
    ↓
输出新的 DXF
```

也就是说，生成一张全新的生产图，而不是修改设计原图。

优点是：

* 不会破坏原始 DWG；
* 不会因修改 BlockDefinition 影响多个块实例；
* 不会遗留隐藏标注；
* 输出内容完全受白名单控制；
* 更容易验证输出 DXF 是否只含允许图元；
* 便于生产端形成稳定接口。

---

## 3. 图元分类技术路线

建议按以下优先级执行，不依赖单一图层。

## 第一层：明确图层规则

例如：

* 标注层；
* 图框层；
* 文字层；
* 中心线层；
* 辅助线层；
* 内部结构层；
* 生产轮廓层。

图层规则速度最快，但不能作为唯一依据，因为原文件已经说明图层和制图习惯存在不规范问题。

## 第二层：明确 CAD 实体类型

可直接识别：

* Dimension；
* MLeader、Leader；
* Text、MText；
* Table；
* Hatch；
* Viewport；
* RevisionCloud；
* 部分剖切和详图符号块。

## 第三层：块和符号规则

根据：

* Block 名称；
* 动态块属性；
* Attribute；
* 嵌套层级；
* 几何特征；

识别：

* 图框；
* 标题栏；
* 剖切符号；
* 放大索引；
* 详图编号；
* 技术说明块。

必须处理嵌套块。不能只遍历 ModelSpace 的顶层实体，否则标注内容可能藏在 BlockReference 内部。

## 第四层：文字规则

对内部技术文字采用：

* 关键词字典；
* 正则表达式；
* 文字样式；
* 所属图层；
* 所在区域；
* 关联引线；

综合判断。

大模型可以帮助把未知文字归类，但低置信度文字不应自动删除，应进入 Review。

## 第五层：空间与几何规则

用于识别：

* 最外围图框；
* 位于主视图之外的说明区；
* 详图圆；
* 剖视图区；
* 放大图区；
* 与主生产轮廓无拓扑关系的孤立图形。

---

## 4. 真正困难的是“主生产视图识别”

一张设计 DWG 可能同时包含：

* 主视图；
* 俯视图；
* 剖视图；
* 局部放大图；
* 多个零件；
* 技术说明；
* 标题栏。

系统必须判断生产设备真正需要哪一组图形。

我会采用以下策略：

### 最可靠方案

由客户在制图阶段增加一个简单、稳定的标记，例如：

* 指定生产视图图层；
* 指定封闭边界；
* 指定 Block；
* 指定基准点；
* 指定零件号属性。

这是成本最低、可靠性最高的方案。

### 次优方案

对同类模板配置“生产区域模板”，例如：

* 相对图框的位置；
* 主视图边界；
* 标题栏位置；
* 排除区域。

### 兜底方案

系统自动聚类所有图元区域，根据：

* 闭合轮廓数量；
* 轮廓面积；
* 视图之间的投影关系；
* 标题和标注位置；
* 主轮廓复杂度；

给出候选区域，让操作人员确认一次。

我不会承诺在所有历史混乱图纸上自动、准确判断主生产视图。这个问题用大模型看图片也很难做到工业级零误删。

---

## 5. 生产几何保护机制

对所有计划保留的图元建立“保护清单”：

* 轮廓线；
* 孔；
* 圆弧；
* 槽；
* 工艺折弯线；
* 生产所需定位线；
* 设备要求的特殊图层。

在输出前后分别计算：

* 图元数量；
* 闭合轮廓数量；
* 每个轮廓面积；
* 周长；
* 包围盒；
* 孔数量；
* 孔径；
* 孔中心位置；
* 拓扑嵌套关系；
* 几何哈希。

输出 DXF 后重新打开，再计算一次。

只有以下条件同时成立才允许交付：

```text
原计划保留几何
=
写入 DXF 前的保留几何
=
重新打开 DXF 后读取到的几何
```

如果发现：

* 面积改变；
* 孔丢失；
* 圆弧被错误离散；
* 坐标变化；
* 单位变化；
* 闭合轮廓断开；

则任务失败并转人工，不得继续推送到生产端。

这比单纯追求“删除准确率 99%”更重要。

---

## 6. DXF 输出适配

不同生产软件对 DXF 的兼容能力差异很大。

需要为每个生产端配置输出 Profile，例如：

```text
Profile A
- DXF 2013
- 保留 Line、Arc、Circle、LwPolyline
- 保留闭合 Polyline
- 不转换 Spline

Profile B
- DXF R12
- 不允许 Spline
- Spline 转折线或圆弧
- 所有 Z 坐标归零
- 图层名称固定
```

不能简单调用一次 `SaveAs DXF` 就认为完成。

必须拿真实输出文件在两套生产端软件中进行：

* 导入测试；
* 图形数量检查；
* 尺寸检查；
* 编程模拟；
* 异常文件测试。

---

## 7. 批量服务和 10 人并发

会议记录要求支持单文件、多文件、压缩包、10 人并发和两个生产端。这里的“10 人并发”不应理解为同时运行 10 个 AutoCAD 进程。

合理架构是：

```text
10 个用户同时提交
        ↓
统一任务队列
        ↓
2～4 个 CAD Worker 按顺序处理
        ↓
任务状态与结果回传
```

需要实现：

* 文件独立工作目录；
* 超时控制；
* 失败重试；
* Worker 定期回收；
* 单文件日志；
* 压缩包防路径穿越；
* 文件大小限制；
* 输出文件校验；
* 原文件和结果文件版本留存。

正式部署前还必须确认 AutoCAD、天河 CAD 在服务器或批处理场景下的授权方式。技术上能并发运行，不代表软件许可一定允许以该方式部署。

GPU 不是这个场景的核心成本。主要资源是：

* CPU；
* 内存；
* SSD I/O；
* CAD 运行环境；
* 软件授权；
* 任务隔离和稳定性。

---

## 8. 实事求是能做到什么程度

在以下范围内：

* 先支持 3～5 种主要图纸模板；
* 生产端明确 DXF 接口规范；
* 客户提供人工净化前后成对样本；
* 图层和块虽然不完全统一，但存在一定规律；
* 复杂异常文件允许转人工；

可以做到：

* 自动删除绝大多数标注、图框、文字、剖视图和辅助内容；
* 自动生成符合指定生产端要求的 DXF；
* 批量任务处理；
* 输出前后生产几何一致性校验；
* 异常图纸自动隔离；
* 每个删除图元具有规则依据和审计日志。

合理的一期目标：

* 标准模板内直通自动化率约 90%～98%；
* 历史全品类、制图极不规范的图纸，直通率可能只有 60%～80%；
* 未自动通过的文件转人工确认；
* 所有通过系统的 DXF 必须满足“受保护生产几何零变化”，否则系统拒绝输出。

这里追求的不是“所有文件 100% 自动处理”，而是：

> 自动通过的文件必须可靠；不可靠的文件必须被识别出来。

这个场景的首个可用版本可以比铁芯场景更快，约 6～8 周能形成演示和内部试运行版本，但要达到生产稳定状态，仍需 3～4 个月测试和适配。

---

# 四、两场景中的大模型究竟做什么

大模型可以承担：

* 根据文件名、图号和元数据选择规则包；
* 解释规则和异常；
* 把审查结果整理成自然语言报告；
* 从规范和会议记录中辅助提取候选规则；
* 对无法分类的技术文字提出建议；
* 向设计人员追问缺失信息；
* 汇总人工复核反馈；
* 帮助生成新规则配置初稿。

大模型不应承担：

* 直接判断孔位是否偏差；
* 根据截图估算毫米尺寸；
* 自由决定删除生产几何；
* 自由修改原始 DWG；
* 在无法解析图纸时猜测通过；
* 代替设计人员确认工程公差。

这套系统即使完全不接大模型，也应能够执行核心几何规则。大模型是上层 Agent 和交互层，不是精确 CAD 算法的替代品。

1. 可以按固定范围继续；
2. 需要客户补充规则后继续；
