## 0. 怎么用这份表

不要从 3570 条图元问「各自是什么意思」。对每条记录只问：

> 有没有一把不靠猜的钥匙，能接到作者已经写好的表上？

| 档 | 含义 | 本图 |
| --- | --- | --- |
| A | 已经是语义：块属性 / 命名字典 | 标题栏、明细、序号关联 |
| B | 能抬一层：稳定块名、handle 关联 | `PC_*` 块、`TH_XuHaoEntity`↔行 |
| C | 只是几何：可定位、可量、可数，不命名 | Line / Arc / Dimension… |
| D | 拒绝抬升：类名在、业务字段不在 | 序号内部参数、算单、出图 |

规则：**没有代号、图号、序号、块名这四类键之一，就不要给业务名字。**

升档必须写得出证据卡。写不出就停在 C/D。

```text
对象 =
证据 =
连接 =
几何 = （可选，仅定位）
禁止 =
```

## 1. 对象类型

真正能进模型的很少，不是 3570 个。

| 类型 | 本图数量 | 身份（主键） | 档 | 从哪来 | 不是什么 |
| --- | ---: | --- | --- | --- | --- |
| `Drawing` | 1 | 图号 `5TBC.384.A110050.2` | A | 标题栏「图样代号」 | 不是文件名，也不是 DWG 路径 |
| `TitleBlock` | 1 | 块参照 handle `438F` | A/B | `PC_TITLE_BLOCK` 30 个属性 | 不是从图框线认出来的表 |

## 3. 链接

| 链接 | 从 | 到 | 基数（本图） | 证据 | 没有证据时 |
| --- | --- | --- | --- | --- | --- |
| `HAS_TITLE_BLOCK` | `Drawing` | `TitleBlock` | 1—1 | 块名 `PC_TITLE_BLOCK` | 不认图框线 |
| `HAS_BOM_ROW` | `Drawing` | `BomRow` | 1—24 | 块名 `PC_MXB_BLOCK` | 不切表格网格 |
| `POINTS_TO_ROW` | `Xuhao` | `BomRow` | 24—24 全连上 | `PC_BOMXHRELATEDIC` 键 `序号#气泡Handle十进制` | 不读气泡字、不按邻近 TEXT |
| `SAME_DRAWING_NO` | `TitleBlock.图样代号` | `PC_TYDH_BLOCK.图样代号` | 本图相等 | 两个属性值 | 不等则出问题，不改主键 |
| `OCCURS_AS` | `PartOccurrence` | `BomRow` | **未建** | 需要块名或邻近序号对上 `code` | 对不上就不要链 |
| `LOCATED_ON` | `Entity` / `Xuhao` / `TitleBlock` / `BomRow` | `Drawing` | 多—1 | 同一次抽取 | |
| `HIGHLIGHTS` | `Xuhao` | `Entity`（同一 handle） | 1—1 | 同一 handle | 气泡就是那条图元 |

跨图链接（本 drop 里有没有零件图 `8TBC.051.A110050.151`）**先不建**。要建也是 `BomRow.code` → 另一张 `Drawing.drawing_no`，文件名对不上就记缺口，不模糊匹配。

## 4. 证据卡：箱底

```text
对象 = BomRow:8TBT.055.T00001.1
证据 = PC_MXB_BLOCK@4575.代号 / 名称「箱底5336×…」 / 数量 1
连接 = POINTS_TO_ROW
       字典 1#8042 → Xuhao@1F6A（0x1F6A = 8042）
几何 = 可选：高亮 1F6A；不要用周围 Line 反推「这是箱底」
禁止 = 从轮廓线聚类出「箱底」；从气泡几何读序号
```

图元里没有一条叫「箱底」的线。名字来自明细，图元只负责指到那块图。

## 5. 本图立刻能做的对账（还不是动作类型）

这些是以后 `cadtasks` / 审图 recipe 的输入，本草稿只列断言，不实现。

| 断言 | 用法 |
| --- | --- |
| `drawing_no == drawing_no_alt == 文件名主干` | 图号一致；文件名多 `_1` 要先剥页后缀再比 |
| 每个 `BomRow` 有且仅有一个 `POINTS_TO_ROW` 反指 | 本图 24/24 |
| `BomRow.code` 非空且不是 `\` | 第 20 行失败 |
| `material` / 重量字段空 | 完整性问题，不是抽取失败 |
| `qty` vs 图上 `PartOccurrence` 个数 | **现在不能做**：`OCCURS_AS` 未建 |

## 6. 禁止

- 用 Line / Arc / Hatch 聚类得到零件名。
- 用晓量 L2 `table_grid` 覆盖 `TitleBlock` / `BomRow`。
- 从 `TH_XuHaoEntity` 内部字段读序号（没有）。
- 把 `TH_DimLeaderUA` / 基准 / 箭头线建成粗糙度、基准字母。
- 把 `MYX*` 在对上代号之前叫成明细名称。
- 把图层名当成对象类型（「轮廓层上的线 = 油箱」）。
- 把 `qty` 当成已经在图面上数过的物理件数。
- 假装有算单、项目树、出图 PNG。

## 7. 何时搬进 `ontology/`

满足再另开 spec，不要把这份笔记当成类型真理：

1. 至少再抽 1–2 张图，确认标题栏 tag、明细 8 列、字典键格式相同。
2. 抽查 `MYX*`（或其它零件块）能否稳定接到 `BomRow.code`；能则启用 `OCCURS_AS`。
3. 身份规则写死：`Drawing` 用图号，不用路径；`BomRow` 用行 handle；`Xuhao` 用气泡 handle。
4. 实例仍留在 `data/datasets/`，类型定义才进 `ontology/`。

本草稿只保证：在这张下节油箱上，按这 6 类对象建模，不会把 3570 条线误当成业务语义。
